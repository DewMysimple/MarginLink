# 同名附件替换事务

1. 对所选目录和附件名做只读磁盘预检。把普通文件的真实路径、父目录和文件身份交给实际 Obsidian Modal，显示 Vault 相对路径、来源名和无备份警告。默认聚焦取消；关闭或取消即丢弃本次授权。
2. 未占用路径沿用排他创建、完整副本恢复及来源删除流程。冲突只能使用这次确认的目标快照，按精确路径串行防重。复核来源、目标、上下文、父目录及可写性。
3. 在同目录排他创建短期文件，复用二进制分块、长度、落盘和 SHA-256 校验。发布前再次检查两端与 staging 身份。一笔同目录 rename 换入新内容；错误时保留旧目标、来源并清理自己的 staging。拒绝目录、路径逃逸、符号链接以及来源与目标共享同一身份的情况。
4. 等公开的 Vault 观察器确认目标的新文件 stat，Markdown 还核对 metadataCache 更新。沿用已有路径级预览失效。用户从已指向该附件的卡片进入时只核验原文和目标；从纯文本选区进入时沿用一次原生编辑。重新链接其他目标仍走原有入口。
5. 发布后若宿主刷新或选区提交失败，提示目标已替换、来源保留。用户可从库内路径完成关联，避免再次覆盖。来源清理失败时复用只重试删除的按钮，每次重验内容。
6. 先通过隔离文件系统故障注入，再用真实 Windows Obsidian 检查按钮、取消、同路径刷新、笔记原文、附件字节与原生编辑。保持 schema 2、minAppVersion 1.10.6，验收后生成 0.3.3 安装包及源码。
