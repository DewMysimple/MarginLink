# 同文件引用合并设计

每个 MarkdownView 持有一个按全文顺序构造的索引。解析器给出原始范围，resolver 返回 TFile.path 和 subpath。路径相同的成员共用 file: 前缀的显示键；解析失败各用自己的偏移。列表沿用原始 occurrence，通过当前源文本计算行号。

同批首次测得的成员按源文顺序入缓存，最先测得的成员为当前文件卡提供正文锚点。因此从笔记中段打开也可就地显示。视口移动、编辑器虚拟化、补测更早的段落，都保留已分配的锚点与左右栏。卡片以组键复用，跟随正文自然裁剪。源文、布局几何或解析结果变更时复核卡位。

连线与卡片独立管理。测量范围内的成员按自己的偏移求路，端口在卡边按全文顺序分散；两端相距过远时，各端的配对编号分别随正文滚动。其他文件卡即使当前没有可测量的连线也参与避障。折叠和显式布局切换仍按当前视图生效。

聚合在四种布局中都提供临时只读卡位，完全手动保留原模式的独立初排。关闭后正常加载逐处记录。全局设置沿用 schema 2 的布尔白名单。

计数按钮与打开文件的按钮互为兄弟。列表由当前视图管理，包含每次引用的来源位置、别名、目标子路径及单处操作。定位沿用该视图的编辑器或阅读模式滚动接口，短暂强调原引用。共享文件直接打开；重链使用既有选区事务校验。源文、文件解析、视图销毁或开关变化使列表失效。
