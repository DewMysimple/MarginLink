## 一、录屏逐帧证据与缺线判断

分析对象为 `PixPin_2026-11-16_18-04-27.mp4`。解码了全部 **120 帧**，画幅 **1134 × 898**，时长 **5.000 秒**，录制采样率 **24 FPS**，帧号从 0 开始。以首帧为参考，在相同横向区间内用灰度模板作纵向归一化互相关。连续跟踪链接段首行、左侧 `Scene Graph` 卡片标签、其上方编号及右侧连线拐角，用另一标题和其他卡片可见时的位置交叉核对。以下为**视频像素**，向下为正；差值等于卡片位移减正文位移。

| 帧 | 时间（秒） | 正文 | 卡片 | 差值 | 画面含义 |
| --- | ---: | ---: | ---: | ---: | --- |
| 22 | 0.917 | +5 | 0 | −5 | 正文开始移动，卡片还在首帧位置 |
| 27 | 1.125 | +295 | +126 | −169 | 同方向滚动期间，卡片落后 |
| 33 | 1.375 | +112 | +304 | +192 | 反向后，两层偏差换向 |
| 43 → 45 | 1.792 → 1.875 | +173 → +85 | +196 → +196 | +23 → +111 | 正文上移 88 px，卡片、编号、连线拐角连续三帧停在同一位置 |
| 46 | 1.917 | −78 | +166 | **+244** | 全片测得的最大相对错位 |
| 105 → 106 | 4.375 → 4.417 | +200 → +200 | +187 → +200 | −13 → 0 | 覆盖层追上原文；其后至第 119 帧都对齐 |

第 22–105 帧共 84 帧，其中 **79 帧**的相对错位超过 1 px，**17 帧**超过 100 px，绝对错位中位数为 **51 px**。本片中被跟踪的编号、右侧线拐角和左侧卡片具有相同的逐帧位移。这组证据应将诊断重点放在**正文与整层装饰之间的运动时序**。录屏没有滚轮事件时间、主线程调用栈或原生显示器刷新时间，应用的真实 FPS 和具体长任务需另行测量。全部 120 帧的数值见文末。

**当前实现能够解释的部分。** `margin-overlay.ts` 监听滚动后排入 rAF，随后进入完整 `render()`。渲染会收集锚点、投影卡片，并调用 `paintConnectors()` 和 `updateContinuations()`。当一对端点均完整入屏而无路，或路线超出可见边界时，整批路由签名可能包含随 `scrollTop` 变化的边界；视口每移动 1 px 都可能使签名失效。已有路径即使复用，绘制仍会逐段设置 SVG 属性，编号也会逐个隐藏并重新定位。`TextObstacles` 已有预扫描区和缓存，但失效时仍需 DOM 测量。这里列的是可测的重复工作，不能从视频把哪一项直接定为唯一瓶颈。[滚动与绘制](https://github.com/DewMysimple/MarginLink/blob/27c4e2d31f6aa3e0f169a6637e653558c39d084a/src/view/margin-overlay.ts) · [批量路由](https://github.com/DewMysimple/MarginLink/blob/27c4e2d31f6aa3e0f169a6637e653558c39d084a/src/view/connector-batch.ts)

**为什么还有卡片没有线。** 在 0.2.15 中，已有 `complete`、`pending`、`offscreen`、`blocked`、`continuation` 等状态。端点完整可见而当前搜索没有返回可绘路径时，插件会尝试成对的编号。若无法同时为两端找到合适位置，也可能没有可见提示。截图中有成对数字，符合现有续接逻辑；仅凭截图不能认定某个目标在几何上绝对无法连通。实际描边是标有 `data-segment` 的路径，隐藏的逻辑路径用来记录关系，仅计数逻辑 SVG 会误判。验收应逐一说明每个可见关联当前展示了什么。

## 二、0.2.16　单击链形图标打开面板

`src/editor/drag-controller.ts` 现有 `pointerup` 只在 `valid && dragging && side` 时调用 `SelectionAction.open()`。所以轻点无反应是入口条件造成的。保留当前选区捕获逻辑，使同一手势只结算一次。

- 主按钮按下时捕获有效选区；在手柄上释放且未越过拖动阈值，打开已有面板，默认焦点给文件搜索。越过阈值后沿用既有拖放行为，有效页边放下才打开。拖出去再拖回正文、Esc、失焦、取消、其他指针释放和选区过期都正确结束该次操作。
- 手柄单击、既有 Enter／Space、命令和有效拖放都走同一个打开入口，保留仓库原有的别名校验和单步撤销。浏览器在 pointerup 后派发 click、键盘按钮激活或页面缩放时都只能产生一个面板。一旦拖动成立，不得在释放后补开一次“单击”面板。
- **验收**：选中 `streams`，普通单击即可打开；临界距离两侧各测一次；合法拖放、非法放下、键盘打开、取消、不同窗格分别测试。关闭面板后原文和选区符合原有行为。已生成的文件卡片继续支持整卡拖动。

## 三、0.2.17　在“已有文件”识别库外路径，确认后剪切进库

截图中的 `"C:\Users\16033\Downloads\streams.html"` 被当作仓库模糊搜索。当前 `FilePicker.showFiles()` 从 `vault.getFiles()` 枚举已有目标。请扩展这一个面板，在同一位置处理名称搜索、库内文件和库外本地文件。

1. 接受原样绝对路径和整条路径外围配对引号，保留路径内部空格、中文、后缀与大小写。例如裸路径 `C:\Users\16033\Downloads\streams.html` 和带双引号版本应解析到同一文件。在相应桌面系统支持原生绝对路径。只解析当前输入的明确路径；普通关键词继续走原有搜索。异步检查带输入代数，过期结果不能覆盖用户后来粘贴的路径。
2. 当路径实际指向本库中的文件时，解析到那个精确 `TFile` 并直接关联。对库外路径只读确认是可访问的普通文件；目录、非法路径、无读取权限、源已消失都显示具体原因。确定库内外和同一文件时要处理规范化路径、Windows 大小写及符号链接。对链接或重解析点的移动语义无法验证时保留原件并解释原因。
3. 复用现有三个预设目录和默认项，放在同一份插件设置中。展示**来源路径、目标文件夹、最终库内相对路径**，允许更换预设及处理重名。例：源为上述 `streams.html`，目标为 `资料/网页/streams.html`，别名为 `streams`，最终正文为 `[[资料/网页/streams.html|streams]]`。目标 HTML、XMind 等附件保留扩展名和原始字节；用于新建 Markdown 的自动补 `.md` 仅适用于“新建文件”。已配置目录失效时允许重选。
4. 输入和预览只读，按下明确标为 **移动到仓库并关联** 的按钮才开始文件操作。用桌面宿主支持的文件接口，在目标目录以排他方式创建，避免同名覆盖和并发抢占。大附件分块读取并校验复制长度与内容摘要；同盘、跨盘都保证以下顺序：**已确认源身份 → 目标副本完整且可解析 → 再校验原文选区或原链接 → 一次写入原生 Wikilink 并确认成功 → 复核源身份和内容未变 → 删除本次源文件**。删除前确认本库文件确实存在且正确；不要在提交前用裸 `rename` 把唯一原件挪走。敏感的绝对来源路径仅在本次操作 UI 中使用，不写入笔记、插件关系数据或普通日志。
5. 把错误按已完成的步骤反馈给用户。重名可选择改目标名，或显式“使用已有文件”并保留外部原件。复制中断且仍为本次独占的临时文件，可清理该临时文件；原文在等待中被编辑、无法确认新文件身份、失败或异常退出时，优先保留完整的源或目标，给出实际路径。源删除失败时显示 **已关联，原文件仍保留在…**，重试仅处理经过再次验证的原件。重复确认不会创建两个副本。撤销正文事务恢复此前文本，已导入的文件保留在库中。不要引入常驻磁盘扫描或一套新的关系数据库。
6. **验收**：用临时目录和隔离 Vault 测试带引号、无引号、含空格中文、库内绝对路径、同名冲突、文件夹误输、失效预设、跨盘或跨卷模拟、源在复制中改变、占用导致无法删除、撤销、快速多次确认与切换笔记。分别校验 HTML、二进制 XMind 的摘要、原件是否应存在和正文实际字节。

## 四、0.2.18　让滚动由同一坐标系统驱动

**先取得基线。** 在隔离 Vault 还原“六个密集链接＋普通段落＋下一标题”。使用录屏中的往返和快速反向动作，记录插件关闭、0.2.15 常驻连线、新实现常驻连线的对照；0.2.19 完成后再加仅编号组。记录硬件、Obsidian 版本、刷新率、缩放、主题和相同输入轨迹。用 Performance trace 和仅开发时启用的计数分别度量主线程、DOM 测量、布局、批量求路、实际 SVG 写入、编号定位和帧间隔。对六条可达和一条受阻的两组夹具分别做暖缓存测试。

- **坐标只有一个来源。** 卡片、线段和两端编号都保存在当前窗格的文档内容坐标里。优先让三者位于宿主原生滚动内容内、能被同一滚动变换带动的装饰层，脱离普通排版，不撑大 `scrollHeight`，不污染 CodeMirror 管理的可编辑 DOM。若宿主挂载点限制需采用等效方案，先用真实合成帧证明同步。阅读视图与编辑视图使用各自真正的滚动容器。
- **把投影和求解拆开。** 纯滚动且缓存几何覆盖当前区间时，只更新必要裁切或可见区投影。已有路段 SVG 的 `d`、成员和卡片相对位置不应改变。不要对每条线重新序列化整批输入、重绘每段或追着 `scrollTop` 改整批缓存键。失败路线也应有合适的失效条件。遇到新区域、原文编辑、软换行、宽度变化、字体变化、手动移卡时，只重新测量受影响区域并使相关路线失效；旧的可用部件仍随正文运动。计算跨帧时按窗格和文档版本丢弃过期结果。
- **同一处提交绘制。** 归并 scroll、CodeMirror 更新、ResizeObserver 与 MutationObserver 在同一帧内重复触发的工作；先读取所需几何，再提交有变化的绘制。保留现有障碍物缓存、纯路由函数与共享主干成员关系，删除已被替代的逐卡／整批更新分支。禁止通过滚动时隐藏、淡出装饰、停滚再显示，或给卡片增加追赶动画来通过验收。
- **通过条件。** 在已测区间内用同一几何反复移动视口，预热后整批求路次数、已有 SVG 路径 `d` 重写次数、完整障碍 DOM 扫描次数、位置持久化次数均为 0。对需加载新片段的场景单列开销。在相同设备和轨迹下报告 p50/p95、最长帧、>50 ms 的主线程任务及其归属。建议以 60 Hz 桌面暖缓存场景插件每帧工作 p95 ≤4 ms 为预算，并以关闭插件的原生滚动为对照。用 DOM 和最终画面两份证据核对：同一次链接的文字与卡片相对偏移几何漂移 ≤1 CSS px，录屏复测应消除原片中可见的连续滞后，报告采样率及视频像素误差。再验分屏、重开、部分裁切、自由拖动和已有卡片相互独立。

## 五、0.2.19　增加“仅显示编号”，并查清缺线

在两个完整设置入口和快捷控制中共享同一枚举，提供四项：**始终显示连线、悬停或聚焦时显示、隐藏连线保留卡片、仅显示编号**。沿用旧设置，不改既有默认值。编号模式是“连线显示方式”，与“直线／折线／平滑曲线”的线型选择独立；切回连线后保留原有线型。

- 为每一次链接出现位置派发唯一编号，使用已有解析顺序与可校验的出现身份，避免用可见卡片的遍历顺序编号。纯滚动、切换显示方式、同页虚拟化和窗格重绘不改号；未修改的同一文档重开结果确定。相同文件在原文出现两次有各自的编号。编号只用于显示，不写进 Markdown、关系库或持久化标记。
- **仅编号**：所有正常关系都有一对相同数字，文字侧就近放在对应链接或同一视觉行的留白，卡片侧就近放在卡边。部分越界时裁切相应端，另一端维持原编号。密集时采用有序错位、最近正文行旁的预留带或紧邻的短引导；不得把多个源端数字推到无关的下一标题旁。可悬停和键盘聚焦任一端追亮对应卡片与原文字。此模式直接走编号绘制，连线路由、共享主干搜索及 SVG 线绘制均为 0。
- **连线模式**：保留通路安全时绘线、当前没有可验证通路时用同一套配对编号续接的能力。在截图对应的六组关系中，分别记录源片段与目标是否可见、测量是否完整、为什么没有安全路径、实际可见段和编号两端是否落位。不要把“有限搜索未找到”说成已证明不可能；有安全路的已知夹具要求 6/6 完整连线，受阻夹具要求完整成对续接。两个端点明明可见时不可因标记位置搜索失败而悄悄消失。隐藏模式收起编号与线，保留卡片；悬停模式按当前关系响应。
- **验收**：以截图中的 `Scene Graph`、`Verse`、`model-assisted`、`ship` 等为样例，验证没有游离数字、错配或重绘闪烁。四模式互切，数字和线不残留，亮暗主题、键盘、重启、同名重复、读写双窗格均可用。拿源端到目标端逐对验收，而非统计 SVG 节点数。

## 六、0.2.20　右键卡片重新链接

1. 在现有卡片菜单中增加 **重新链接文件…**，保留“恢复此卡片自动位置”。未解析、目标已移动或无法打开时也要能重新指定目标。直接进入同一个文件面板，显示当前目标，默认在“已有文件”；复用库内搜索与库外路径移动，用户走新建笔记分支时沿用新建规则。
2. 把“从选区创建链接”和“替换既有链接目标”作为同一提交入口的两种操作。后者捕获源文件、具体出现位置、旧原始文本、目标及别名、文档版本；确认前重新定位并核对。对 `[[旧目录/a.html|streams]]` 仅将这一个出现位置改为 `[[新目录/b.html|streams]]`。无显式别名时保留无别名形式；原 `#标题` 或 `#^块` 能在新目标核实时可保留，不能确认时给出保留/移除子路径的明确选择。取消或失效时不修改原文、不删除旧目标文件。
3. 在支持的编辑模式用一次原生可撤销事务提交。阅读视图从映射出的具体源文本位置进行等价的受校验提交，处理同一文件在其他分栏的未保存编辑；如需借助源编辑视图，应恢复原阅读位置。若源发生变化且无法唯一确认，保留两端文件并提示重新选择。不要全文替换目标名。库外移动分支同样在链接更新成功后才处理原件。
4. 当前布局身份含原链接及邻近文字摘要。替换目标可能连带改变邻卡身份。用事务前后解析结果对齐本次出现位置和可证明未受影响的相邻出现位置，只迁移能够确认的已有手动布局与编号关联。取消、Undo、Redo、切页或重开后，卡片和邻卡的位置按原语义恢复。
5. **验收**：同一笔记内构造两处完全相同的链接和一张紧邻的手动卡，仅重新链接第二处。逐字比较源笔记，仅这次目标改变；确认别名、子路径策略、邻卡位置、编号、撤销和重做。再测失效目标、阅读视图、另一分栏同时编辑，以及库外移动失败。

## 七、保持工程可维护的交付条件

- 保留一套文件选择 UI、一处源文事务提交、一份目录设置和一个按窗格工作的绘制入口。文件系统移动单独封装其阶段和错误；文件面板不直接删文件，路由器不读写 DOM，绘制和编号都不改布局存储。只在存在共同调用者或明确故障边界时提取模块。随新实现删除被替代的整批失效、重复事件监听和数量不一致的设置分支。
