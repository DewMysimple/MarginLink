# MarginLink 三项整改｜Codex 执行提示词

请在现有 [DewMysimple/MarginLink](https://github.com/DewMysimple/MarginLink) 仓库里直接修改插件，完成以下三项整改、运行测试并生成可安装的构建产物。开始时读取仓库的 `AGENTS.md` 和当前工作树，保全已有改动。下面给出的源码入口来自 v0.2.0；如果当前分支已演进，沿用实际实现，已满足的需求做回归验证即可。

**交付时我会亲自走这条路径：** 在「未命名 3」里点左侧 MarginLink 图标，右边立即出现完整设置。我选「自由拖动」，抓住「未命名 2」卡片的文件名，把它放到右侧偏下。松手后我单击卡片进入「未命名 2」，再点后退。「未命名 3」中那张卡片应该还在我刚放下的地方，连线仍接到同一处文字。

## 1. 点击左侧图标，直接展开右侧设置

- 在 Obsidian 左侧竖排工具栏（Ribbon）默认注册一个 MarginLink 图标，悬停提示“打开 MarginLink 设置”。右侧栏折叠时，点击一次即展开右侧栏，在顶部标签行显示并选中 MarginLink 标签。点到后直接能调整连线、布局、卡片外观。
- 右侧标签承载**完整设置**，复用已有设置页的表单与偏好状态。调节后当前笔记即时生效。已有标签就激活它；关闭后再点击可以重开。快速连续点击也只创建一份面板。尊重用户收起侧栏和拖动标签的行为。
- 复用现有命令与原生设置页。优先用 Obsidian 公开的 `addRibbonIcon`、`registerView`、`ItemView` 和 Workspace leaf API，避免向其他插件的工具栏插入 DOM。用户点入设置后，“当前笔记”的操作应作用于刚才操作的 Markdown 视图；多个分屏时根据最近操作的笔记判定。
- 源码入口：`src/main.ts`、`src/ui/settings-tab.ts`、`src/ui/quick-controls.ts`。检查右侧视图关闭、重开及插件重载时的监听器清理。

## 2. 移除卡片右上角六点握柄，直接拖整张卡

| 用户操作 | 期望行为 |
| --- | --- |
| 单击卡片的图标、文字或空白处 | 打开目标文件。Ctrl/Cmd 加单击延续原来的新标签行为 |
| 在自由或吸附模式下按住上述任意位置，移动达到现有约 5 个 CSS 像素的阈值 | 开始拖动。卡片和连线同步更新，支持放到左右任一合法空白区 |
| 在合法位置松手 | 提交一次位置，停留在当前笔记；抑制本次拖动产生的点击，下一次正常单击仍可打开文件 |
| 按 Esc、失焦、指针取消或在正文内松手 | 恢复拖动前的位置，取消本次提交 |
| 键盘聚焦卡片 | 保留打开、方向键移动、跨侧和恢复自动位置的能力，焦点落在卡片自身 |

移除六点图标、专用按钮及其独立的键盘焦点，把交互接到卡片本体。覆盖横向、正方形和极简图标三种外观。**这次移除的是已有卡片上的握柄。** 正文选中文字时出现的小链接手柄继续用于创建原生双链。保持自动布局模式的现有含义。

源码入口：`src/view/margin-overlay.ts`、`src/view/card-drag-controller.ts`、`styles.css`。复用现有拖动阈值和合法落点计算，关注整卡同时接收 pointer 与 click 后的事件顺序。

## 3. 修复切换笔记后卡片位置复位

**优先复现这个问题。** 在隔离测试库准备 A、B 两篇笔记，让两者都引用同一个文件。给 A 的卡片与 B 的卡片分别选一个明显区别于自动排列的位置。放下后立即切走再返回；用户无需点击保存或等待。位置按“源笔记 + 这一次双链出现”恢复。

1. **先区分记录丢失与显示错误。** 检查松手后的内存记录、切页时读到的源路径及链接集合、回到 A 时命中的布局记录，以及最后绘制的卡片边界与连线端点。只要源文与窗口几何相同，卡片应恢复到同一落点，允许像素取整误差。
2. **核实切页期间的清理时序。** v0.2.0 的 `MarginOverlay` 会在文件或编辑器版本变化后调用 `LayoutStore.reconcile`。如果 A 的路径与 B 的旧链接集合同时出现，清理器会删除 A 的有效记录。该路径是排查线索，实际根因以复现为准。编辑和阅读视图在加载、暂时空白或仅渲染局部内容时，只做显示或延后恢复。清理须基于已确认属于相应源笔记的完整文档和真实变更。
3. **保证合法松手立即可恢复。** 先提交到正确源笔记的内存布局，再安排持久化。处理连续拖动、快速切页、正常重启和异步写入顺序，避免旧快照覆盖新位置。恢复现有用户已保存的有效布局。右栏展开、窗口变窄或锚点滚出屏幕时仅调整当次显示，再次有空间时恢复原有相对位置。
4. **限定清理范围。** 检查 `src/main.ts` 中 rename/delete 监听的全局 `layouts.clear()`。重命名或删除无关文件应保留其他笔记的位置。删除原生双链时，卡片随该处引用消失。完全相同且无法区分的重复引用沿用安全回退，避免把位置套给另一处双链。
5. **沿用现有数据边界。** 原生 Wikilink 是唯一关联来源。只把视觉位置保存在现有插件 `data.json`。开面板、移动卡片、切换文件的全过程，笔记 Markdown 应逐字一致。沿用按锚点保存的相对坐标，确保滚动后仍对应原文。

重点文件还包括 `src/core/layout-store.ts`、`src/core/layout-identity.ts`、`src/reading/reading-anchors.ts` 和 `src/view/layout-engine.ts`。只改与复现和修复有关的代码。

## 验收与交付

用真实操作入口覆盖下表。在同一视口、字号和滚动位置下，比较卡片放下后及返回时的侧别、实际矩形和连线端点。**“立即切走”用例中不得主动调用内部保存函数，也不要在切页前插入等待防抖落盘的延时。**

| 用例 | 可观察的通过标准 |
| --- | --- |
| 右侧栏收起，单击左侧图标；连续再点两次 | 一次点击即可看到完整设置。窗口内只有一个 MarginLink 设置标签，修改能立即反映在笔记上 |
| 分别从图标、文件名和卡片空白处拖动；再试单击及 Esc | 三处都可拖，放下只移动，单击只打开，取消能回到原位。卡片无六点按钮，正文建链手柄正常 |
| 在同一标签执行 A → B → A；再从 A 点击卡片打开目标并后退 | 两条导航路径都恢复 A 的手动落点。B 引用同一文件时可保有自己的位置 |
| 关闭重开 A，正常重启 Obsidian，切换阅读/编辑视图 | 有效手动位置可恢复，旧设置可读。删除一个双链不会从布局记录重新生成该卡片 |
| 拖好后展开设置侧栏、缩窄再恢复窗口；重命名一个无关附件 | 两侧空间变化时卡片不盖住正文。空间恢复后回到原相对位置，无关操作不会清除布局 |

在现有测试中加入能捕捉上述回归的用例，按仓库约定执行 `npm test`、`npm run lint`、`npm run build`、`npm run package`；有 Obsidian 桌面环境时，在隔离测试库运行 `npm run test:desktop` 并补测上述操作。缺少桌面宿主时，完成可运行的检查，明确列出待实测项及复测步骤。

最后用中文交付：逐项说明三项整改的实现结果、位置复位的已验证原因、实际运行的检查，以及可安装包或目录的准确位置。同步相关使用说明，依仓库既有 Git 交付约定收尾。现在开始实施。
