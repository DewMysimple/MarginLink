## 共同复现场景

在隔离测试库制作一页类似截图的笔记：一个普通段落，接一段含六个原生 Wikilink 的正文，然后紧跟一个长标题。按正文顺序放入 `Early Access`、`dives`、`Verse`、`Scene Graph`、`model-assisted`、`ship`；给标题、普通正文和相邻链接都留在测试画面里。使用可读行宽、正方形卡片、自由布局、常驻连线。将左侧的三张卡排成截图里的 `Scene Graph / Early Access / Verse`，在右侧分别放 `dives / model-assisted / ship`。再准备一组把 `ship` 放在右上、`dives` 放在右下的摆法，以便核对共用竖干。每次记录窗格宽高、缩放、线宽、卡片位置和线型，保证同一场景切换模式可比。

源端沿用实际链接文字片段的上沿或下沿中点，卡片端可从合适边界中点接入。保留 0.2.8 的内容坐标、滚动裁切以及 0.2.9 的正文避让。所有关系均来自原生 Wikilink。共享线段的成员仅存在于当前窗格的绘制数据中。

## 0.2.11　修复“始终显示”缺线

**已核实的原因。** `connectorRoute()` 只枚举有限的离开距离（0、3、7 px 的增量）和少量候选路线；候选全部被避字检查拒绝时返回 `undefined`。`MarginOverlay.place()` 随后把 SVG 的 `d` 写为空，并缓存这次几何签名。“始终显示”的 CSS 只给已有路径设置透明度。0.2.9 的既有测试也明确允许无路时省略。先为每个截图目标分别记录有无文字矩形、是否被裁切、有效路径与样式状态；仅凭静态图无法断定每条缺线的成因。[路由实现](https://github.com/DewMysimple/MarginLink/blob/55f403362974850bc477887395da9e7e3c807af1/src/view/connector-renderer.ts) · [渲染入口](https://github.com/DewMysimple/MarginLink/blob/55f403362974850bc477887395da9e7e3c807af1/src/view/margin-overlay.ts)

**先加入一个旧版必失败的几何测试。** 单位为 CSS px，源文字框左上和右下是 `(100,100)–(140,116)`，卡片左上 `(500,70)`、大小 `84 × 84`，正文列 `x=20…400`，障碍框 `(160,60)–(180,160)`，线宽为 2。0.2.10 的三种线型在此输入上均返回空。存在的一条通路是 `(120,100) → (120,55) → (490,55) → (490,112) → (500,112)`。验收查连续性和避让，不要求逐点照抄这条示例折线。

- 为源文字提供向上和向下的出口，并从障碍物边缘、行间空隙及两侧页边生成可达路径。优先复用已测得的窗格几何；已有便宜候选失败时再扩大搜索。按实际描边宽度检查整条线路及曲线弧段，保护正文、标题、行内代码和其他卡片。保留上一条仍然合法的路径至新结果可用，已经不合法的旧路径要及时撤掉。
- 区分可安全连通、测量尚未就绪、端点已出视口、可测但确实无通道。虚拟化、重新换行、窗格宽度、障碍物、线宽或卡片位置变化后，及时作废相应失败结果；纯滚动几何不变时只投影已有路径。临时测量缺失时在实际数据就绪后重试，避免逐帧空转。
- **更新上一版“无路可省略”的规则。** 两个端点都可见而确实没有安全通道时，常驻模式给源端和目标端显示一对相同的短编号续接标记（同屏不同关系可区分），指向或键盘聚焦任一端时同时高亮两端。标记仅在覆盖层、安全留白中出现，通道恢复即换回完整连线。这个极端降级单独计数。正常六链接夹具必须六条都能追完整，不能靠编号通过。悬停模式按当前关系显隐，隐藏模式同时关闭线与续接标记。
- **验收**：六对端点完整入屏且夹具明确有路时，无需鼠标靠近即可逐对从原文字追到卡边，完整数为 **6/6**；已知绕障用例三种线型都能通。另用完全封闭的上下出口验证续接、恢复，以及滚出视口后的正常裁切。独立检查实际可见描边、透明度及连通性，避免只统计 DOM 中的 `path` 数量。

## 0.2.12　自由拖动只改变当前卡片

`StableLayout.update()` 在一个已有锚点的手动值改变时会清空整组 `entries`。`positionFromDrop()` 会让当前卡与已占用矩形避让，`displayPosition()` 还会在恢复位置时避让。松手之后其他卡能够重新选侧、换槽，即使存储层只写入这一张卡。分别修拖动预览、释放后的刷新和重新载入三个阶段。[布局缓存](https://github.com/DewMysimple/MarginLink/blob/55f403362974850bc477887395da9e7e3c807af1/src/view/stable-layout.ts) · [拖放与排布](https://github.com/DewMysimple/MarginLink/blob/55f403362974850bc477887395da9e7e3c807af1/src/view/layout-engine.ts)

- 自由模式中保留鼠标抓点和合法页边约束。落在合法区域就按实际落点摆放，包括用户有意把卡片部分叠在一起；当前操作或聚焦的卡片可临时在上层。禁用自由模式下因其他卡片触发的推开、吸附和自动换侧。明确选择吸附模式时，只让当前卡按网格吸附；自动模式继续负责自动排布。
- 拖动开始时保留该窗格里已定位卡片的内容坐标、侧别及相对原文偏移，按**本次链接出现位置**局部更新。其他手动卡及还没手动拖过的自动卡同样受保护。放下只写当前卡片的布局记录，沿用原有身份和相对坐标格式。右键“恢复此卡片自动位置”只作用于该卡，用户显式选择全局整理时才按其范围重排。
- **验收**：将 `ship` 从卡角抓起，跨侧、拖到 `dives` 附近、部分重叠、合法放下，再分别试 Esc 取消和非法落点。记录按下前、每帧预览、松手后一帧、保存回调和下一次渲染的几何。在固定正文几何下，每张未操作卡的横纵位移均 ≤ 1 CSS px，侧别不变；只有目标布局记录可改变。键盘移动也遵守这一规则。切页、重开后检查手动位置和有意重叠的恢复。滚动时按相对文字的坐标比对。连线可因新位置而重算，线路重算不能反向移动卡片。

## 0.2.13　消除卡片边缘的过短折尾

绿框中 `ship` 的整条线足够长，问题在**最后一次转向后只剩几像素就撞到卡边**。0.2.10 以避字留白加半个线宽等因素确定入卡引线，在常用线宽下会产生约 3 px 的末段。

- 对完整路径压缩重复点、冗余共线点和立即回折。用“最后一次可见方向变化到卡边的距离”评价末段。优先改用面向来线的卡片端口，其次移动最后一个转折或直接合并进同向线段。保持正文端的安全出口和卡片真实位置。
- 建议起始阈值为 **12 CSS px 或 3 倍实际线宽，两者取大**。它用于惩罚可消除的装饰性短折尾，在示例夹具中作为验收线。文字端为离开字形所需的短引线另行处理。两端原本就很近且可以直达时，允许一条干净的短线或短弧，不要绕圈凑长度。
- **验收**：复原“长水平段 → 靠近 `ship` 的竖折 → 几像素短横入卡”，把卡放在同高、高于和低于锚点的位置，左右各验一次。在有替代端口或充分空间时，路径应直接入卡或留下足够的末段。拖动目标轻微越过等价候选时，避免端口来回跳。验收统计末次转折，不以整条路径的总长度达标。

## 0.2.14　平滑模式的分流与入卡应自然转向

当前 `segments()` 主要由直线 `L` 组成，只有部分角点追加局部二次曲线 `Q`，而且可尝试零圆角。斜跨到卡片的主体因此可能仍是一条长直线。截图反馈针对这种突兀的直支线；用户希望保留真正能共用的直主干。

- 对确实需要转向的进、出段，根据文字出口、共享主干方向及卡片入口方向生成具有切向的曲线。可以使用三次 Bézier 或分段拼接。分支进入或离开主干时沿共同切线衔接，向卡边平顺收束；几何上共线的区间允许走直。为没有共享主干的单条斜向连接也生成符合端点方向的路线。
- 控制点和弧长应与可用空间匹配。曲线完整描边仍受障碍物约束，受阻时换候选通道或调整控制点。不要默认退化成“长斜线加一个几乎不可见的圆角”。平滑模式切换后立即更新已有线路与设置预览。
- **验收**：用截图中 `dives` 的大横向距离、高低错位和 `ship` 的分入主干作夹具。对非共线、空间充足的样例，用实际 SVG 几何采样检查起终方向和转向段内的切线方向连续变化，核对分合处两侧切线。只有一个 `Q` 或 `C` 命令不构成通过。另保留一例天然共线的连接，防止为显示“平滑”硬加拐弯。

## 0.2.15　三种线型按条件共用主干

以最后一张截图绿框里的**同一段竖线**为正面样例。每条原文字到文件的关联依然独立；两条路线确实需要经过同一段留白时，该段只画一次。0.2.10 是逐卡各自求路并绘制一个路径，画面偶尔重合不等于共有一段可追踪的主干。

1. 在同一 Markdown 窗格的一批可见关联中，先确定安全通道与各成员的起终点，再比较同侧路线的**连续重合区间**。共享应有足够长度和实际收益；例如可从 24 CSS px 的重合区间开始调试。只在一点交叉、正文两侧不同、合并后明显绕远、穿字或使分支无法辨认时，走各自的路径。卡片轻微移动时，对近似等价的候选保留稳定选择。
2. 三种线型都复用通道、成员和分流点的计算，再各自绘制。**直线**在能直达时保留直连，适宜共享时用清晰的直线段汇入共用直段；**折线**使用水平或垂直主干及正交分支；**平滑曲线**在分合处切向衔接，共用的中段可为直线或适宜的弧段。不要把三种设置都画成圆角折线。
3. 每段共享区间只做一次常态描边，沿主干的透明度和粗细与单线一致。记录每次 Wikilink 出现位置经过的有序线段。鼠标指向或键盘聚焦一张卡片，只高亮它自己的源端、所经主干和目标分支；保留其他分支原样。隐藏、切页、删除链接或切换线型后清理失效段。纯滚动沿用内容坐标，拖动时更新受影响路段并保持其他卡片坐标。
4. **验收**：对三种线型逐一测试 `ship + dives` 的可共享夹具、一条独立支路、只交于一点或分居两侧的反例。正例必须存在可量出的公共区间，反例必须保持独立。以源文字出现位置为单位验证能到达指定卡片，共享主干切勿被计成多条已完成的关系。再删除其中一个成员、轻微拖卡、切换显隐与线型，确认没有悬空短枝、重复加深的线或错误高亮。
