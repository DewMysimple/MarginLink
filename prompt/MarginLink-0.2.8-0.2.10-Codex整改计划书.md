## 共用复现场景

在仓库的隔离测试库建一篇长笔记，使目标段落可以完整经过视口的上、下边缘。沿用用户截图中的段落结构：`Building this together` 标题、一个普通段落、一个密集链接段落，随后紧接可换行的长标题。链接段落按顺序包含 `Early Access`（HTML）、`dives`、`Verse`、`Scene Graph`、`model-assisted` 和 `ship`。调整可读行宽使它们分布在数行，左右页边均能放下正方形卡片。开启常驻连线，先用折线复现，再验证其他线型。参考图里最容易观察的是左右两侧的卡片顺序以及下一标题上横穿过去的紫线。

## 0.2.8　卡片与原文保持相对位置

### 已复现的行为

在 0.2.7 的 `src/view/layout-engine.ts` 中，`layoutCards()` 过滤当前视口之外的锚点，按剩余锚点重算左右侧与避让顺序；`legalize()` 用当前视口的上下界夹住卡片。`src/view/margin-overlay.ts` 还会过滤未完整显示的文字片段；跨行链接的原参考片段被裁掉时，会改用另一个可见片段。这是两条分别需要覆盖的代码路径。

用原版布局函数做了以下几何复现。视口高 420 CSS px，正文横向范围 180–820，视图宽 1000，正方形卡片高 84。数据是纯函数结果，桌面上的逐帧表现由执行者另行验证。

| 输入 | 0.2.7 实测结果 | 整改后的断言 |
| --- | --- | --- |
| 单张手动卡，纵向偏移为 0，文字参考点依次为 60、50、40、30 | 卡片中心依次为 60、50、50、50，末帧偏离文字 20 px | 卡片中心依次为 60、50、40、30，上缘自然被裁切 |
| 同段六张尚未手动定位的卡片，所有文字向上移动 80 px，`ship` 原本在右边卡组上方 | `ship` 中心从 86 跳到 288，跑到右边卡组下方 | 保留原排布，中心到 6；视口只显示与卡片相交的部分 |

第二例可用 `Early Access(490,180)`、`dives(723,180)`、`Verse(351,203)`、`Scene Graph(455,203)`、`model-assisted(620,203)`、`ship(783,226)` 六个锚点复现。使用左右均衡、自由布局、16 px 边距和普通尺寸；第二帧对所有 y 同减 80。

### 实施要求

1. 以**源笔记中的这一次链接出现位置**作为卡片的锚点。同一目标被链接两次时，两张卡分别跟随各自原文。为每次出现选择稳定的文字参考行；跨行时卡片的位置基准独立于当前用于画线的可见片段。沿用已有手动记录对参考位置的定义，保证旧卡升级后在原来的位置打开。
2. 在笔记内容坐标中确定所在侧及相对文字的偏移，纯滚动时只把已有布局投影到当前笔记窗格，再据真实滚动区域裁切。卡片与文字可以一先一后越界，二者各有尺寸。部分露出的卡片应继续显示露出的部分；当某个文字片段刚刚出界，不可引发其余卡片重新排队。裁切外的区域不能拦截点击或滚轮，顶部标题栏、侧栏始终可操作。
3. 首次排布、主动放下卡片、真正改变行宽或文字内容时可以重新求解。纯滚动需复用稳定排布，尤其避免“新链接刚进入可见范围，已在屏幕上的卡就被挤走”。支持从笔记中段直接打开、快速翻页、滚出再返回、CodeMirror 虚拟化以及阅读视图的分段渲染。可结合已有解析顺序、按需测量的邻近区段及每个视图独立的内存缓存；避免逐帧读取整篇笔记或每滚动一次写入插件数据。
4. 保留拖拽落点的边界与合法性校验，区分拖放约束与静态展示裁切。复用现有 `side`、`xNormalized`、`yOffset`，核对 `positionFromDrop()`、`src/view/card-drag-controller.ts` 和布局恢复流程。多窗格各取自己的滚动容器与坐标，切换、关闭文件时正确清理临时几何。

**通过条件**　在行宽、字号和卡片尺寸固定时，逐帧独立测量“卡片中心 y − 同一次链接参考行 y”，相对起始值的最大漂移 ≤ 1 CSS px；同侧卡片的上下顺序与左右侧分配保持一致。覆盖滚轮慢滚、反向、滚动条快速拖动、贴上/下边界、部分裁切、完全滚出再返回。分别验自动、自由、吸附布局；至少对手动拖过的卡片、跨两行别名、重复目标、分屏独立滚动，以及阅读和编辑视图各做一次。比较滚动前后的已保存布局记录，纯滚动应为零改写。保留侧栏缩放及切页恢复的既有回归。

## 0.2.9　连线从文字上、下沿出发，避开正文

此次反馈更新了 0.2.3 的正文端四向规则。**左右页边仍然放卡片。** 改动的是线离开文字的位置，以及从文字通往页边时实际经过的区域。单改起点仍可能让后半段穿过其他字。

- 查 `src/view/connector-renderer.ts` 的 `ports()`、`geometry()`、`connectorRoute()` 以及 `margin-overlay.ts` 的 `place()`。现版文字端、卡片端都能选四边，碰撞评分只检查同一个链接的其他片段。原版在链接框 `[420,120]–[492,140]`、同高度右侧卡片的用例中，会从 `(492,130)` 沿文字中线向右画。把此例加入回归。
- 只给**文字端**提供真实文字片段上边或下边的水平中点。跨行别名取实际有字的片段。优先朝邻近的行间空白出线，沿可用空隙走到对应页边，长距离向上或向下的部分尽量放在正文列外。卡片端按来线方向接在合适边的中点。当卡片与文字恰好同高，也应能在有足够行距时画出完整路径。
- 使用该窗格已渲染的正文、其他链接、标题及行内代码的文字矩形，检查**整条路径**。检查范围计入半个线宽及小量留白，涵盖折线拐点、曲线中段和链接下划线。仅在源端的受控接触处容许贴边。几何数据按可见区和内容几何变化复用，避免每张卡每帧各扫一遍 DOM。SVG 保持 `pointer-events: none`。
- 保留直线、折线、曲线和原有显示模式。在所选样式下先尝试可读的完整路径；例如同高卡片需要绕开文字时，可保留短引线，将其余部分按所选样式连接。极紧排版确实没有安全路径时，**只省略这一条线**，保留原生双链、卡片与悬停高亮，空间恢复后自动重画。连线路由不能移动卡片或改变已保存位置。
- 同时更新共享设置预览和旧的四向断言。测试要从实际 SVG 路径映射到屏幕坐标，用独立的正文 `Range` 几何检查交叠。足够行距的左右同高场景必须各有完整连线，防止“所有线都隐藏”误过验收。

**通过条件**　在密集段落里，着重看 `gameplay framework`、`model-assisted` 和下一行标题 `Get updates on industry innovations…`。左右卡片、换行别名、三种线型、普通及最大线宽均要检查；已画线的正文起点只在上沿或下沿中点（误差 ≤ 1 CSS px），正文和标题的受保护文字区域内没有线段穿过。常驻、悬停、隐藏三档分别按用户设置工作。在 0.2.8 的滚动场景复核相同指标。

## 0.2.10　HTML 卡片改用灰阶网页图标

参照用户发来的蓝绿色浏览器旋涡小图，保留“网页文件”的旋转轮廓，绘制为适合 Obsidian 的灰阶版本。当前截图中的细框 `HTML` 文字标签改为**灰阶旋涡主图 + 无外框的 HTML 短标**。这样保留之前提出的四字母识别要求，卡片标题仍显示 `Early Access` 等原别名。

1. 在 `src/view/card-renderer.ts` 的 HTML 专门分支和 `styles.css` 的 `.margin-link-html-icon` 中替换现有文字框。选用简洁、本地打包的矢量图形，灰阶随主题前景色调整。只处理图标，不对整张卡片降透明度。悬停、键盘聚焦、未解析提示和拖动的反馈仍要能区分。样式作用域限 MarginLink 卡片。
2. 匹配 `.html`、`.htm`，扩展名大小写统一处理。常规卡片内以旋涡为主，HTML 短标可放下方；紧凑模式调整内边距与构图，保证四个字母可读且没有裁切。沿用现有无障碍名称和单一“文件名 · HTML 文件”悬停提示，让装饰图形对读屏隐藏。
3. 在 100% 缩放测试亮色、暗色、横向、正方形与最小 32 px 图标卡片；另取一档高缩放复核。截图须是实际卡片原尺寸。对照同屏 Markdown 和 XMind 卡片，检查别名截断、对齐、可点击与可拖动。保持 0.2.7 的原生文件列表识别开关、文件打开方式及已有 Wikilink 行为。
