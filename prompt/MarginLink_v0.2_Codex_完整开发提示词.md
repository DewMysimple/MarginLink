## 1. 不可妥协的产品原则

**所有知识关联唯一来自 Obsidian 原生 Markdown Wikilink。**

示例：

```markdown
We'll have a lot more to share on the road to [[References/product_release_stages.html|Early Access]].
```

插件扫描和解析已有 Wikilink，显示对应的边缘卡片及连线。用户选中文字并建立连接时，仍通过当前 `Editor.transaction()` 机制生成原生 Wikilink；不增加任何新的关联语法。

**绝对禁止**：自定义双链/关系格式、额外关系数据库、笔记 sidecar 文件、写入自定义关联 ID、Frontmatter 关系字段、隐藏 HTML 注释、篡改已有 Markdown 以保存坐标、给链接追加不可见标记；禁止用独立的关系表替代 Obsidian 原生双链。

**允许**：在现有插件的 `.obsidian/plugins/margin-link/data.json` 内保存全局外观偏好及**纯 UI 布局偏好**（用户自由拖拽后的坐标等）。这些信息不是链接关系本体，删除它们应仅让布局回归自动排列，不得丢失任何关联。不得在设置之外创建其他持久化文件。UI 布局数据只引用已存在的 Wikilink 出现位置，不能使无双链的关系凭空出现。严格验证和限额存储的内容；对模糊、过期或冲突的坐标选择忽略而不是错误应用。

## 3. 本轮必须完成的四个核心需求（P0）

### 3.1 连线显示可选「常驻」且可以精细调节

保留现有悬停模式，并新增：

- `always` 始终显示；`hover` 悬停/聚焦/选中显示；`none` 隐藏连线但保留卡片、跳转及原生双链。
- 可选择线型：平滑曲线（默认）、直线、直角折线。
- 线条粗细可调（建议 1–5 px，步长 0.5）、常驻透明度可调（建议 10–100%，默认约 60–70%），激活状态更明显。
- 线条颜色至少提供「跟随 Obsidian 主题强调色」及少量预设色。允许未来扩展颜色选择器，但不要引入沉重 UI 依赖。符合 CSS 主题变量和暗/亮模式。
- 连线从**对应文字可见 DOM 位置**到对应卡片边缘；卡片移动、滚动、窗口/侧栏尺寸、字号/主题改变时同步刷新；不要绘制指向错误文字的线。
- 同一文件被同一笔记多次引用时，**每次 Wikilink 出现都是独立锚点**，各自有独立连线与卡片；不能按目标文件去重。
- 对无效锚点、离屏元素、不足空间和视觉溢出做安全降级；不渲染跨越整个工作区的错误连线。
- `prefers-reduced-motion` 下减少动画。SVG overlay 不能拦截正文选择、滚动、点击；指针事件应由必要的卡片/手柄处理。

验收：在设置面板切换模式，真实视图立即变化；设置在重启后恢复；`none` 不会隐藏卡片或删除 Wikilink。

### 3.2 文件卡片可在正文空白区自由拖拽

在保持当前「选中文字拖到空白区创建链接」原有操作不变的前提下，**新增卡片拖动定位**。必须清楚区分两种拖拽：

- 新建关系拖拽：从选中文字的手柄开始 -> 选择文件 -> 写入原生双链。
- 重新布置拖拽：从已有文件卡片的拖拽柄（建议显式 `grip` / 顶边拖拽区）开始 -> 移动卡片 -> 不触碰 Markdown。

要求：

1. 支持三种布局模式：`auto` 自动排列、`free` 自由拖拽、`snap` 智能吸附。默认可选 `snap`（迁移时不能让旧用户布局突变，详见兼容性章节）。
2. `auto` 沿用并改善当前算法，不能把卡片叠在正文上；`free` 允许在**当前 MarkdownView 内、正文左右空白带**的二维范围移动；`snap` 在拖动时显示对齐/吸附提示、对齐到邻近卡片或栅格并规避重叠；不需要实现一个复杂通用物理引擎。
3. 支持在左右空白带之间移动，穿过正文时可显示拖动预览，但**最终停放位置不能遮挡正文**，不允许覆盖侧边栏、标题栏、状态栏或其他 leaf。
4. 卡片拖动开始时应有明显的移动反馈、占位/边界提示；松手提交位置；Esc 取消并恢复原位置；拖动距离阈值避免把点击打开误判为拖动；在按钮/图标上仍可单击打开文件，键盘可操作。
5. 自动模式不写自由坐标；手动拖拽只修改 UI 偏好，不写 Markdown；可在设置/菜单中对**当前笔记**执行「重置所有卡片位置」，也可对单个卡片「恢复自动位置」。
6. 卡片坐标不要存绝对屏幕像素或宿主窗口坐标：设计一个对窗口、主题、正文字号和两侧空白宽度具有韧性的**相对布局表达**，建议 `side + xNormalized + yRelativeToAnchor` 或可论证的等价方案；在布局宽度不足时暂时安全降级/隐藏，恢复足够宽度时尽可能恢复原自由布局。
7. 滚动长文时用户拖出的卡片不能僵死在视口顶端，也不能无原因漂移。明确设计**锚点跟随/视口裁剪**机制：卡片相对于对应文字垂直位置的偏移随正文滚动同步调整；离屏锚点的卡片和连线适当裁剪；不要用 `position: fixed` 把卡片长期漂在不相关段落。
8. 同屏多个卡片应避免重叠。自由模式冲突时优先尊重手动布局，但提供合理的碰撞反馈/避让以及「一键整理」。
9. 分屏与同一笔记的多个 MarkdownView 不能串位置：视觉偏好可以按源笔记共享，但各 leaf 独立计算实际布局。禁止持久化 leaf DOM 节点、窗口像素或运行时对象。
10. 实现 Pointer Events、`setPointerCapture`（如适用）、`pointercancel`、切视图、卸载插件、视图销毁及失焦的安全清理；移动到界外时可取消或回退，绝不能卡在“正在拖动”状态。

#### 关于「记住卡片位置」的设计约束（非常重要）

允许在原有插件 `data.json` 中保存**UI 坐标记录**，但不能创建第二套关系数据。为每次原生 Wikilink 出现建立可恢复的弱身份匹配，建议基于 `source note path + target path/subpath + link raw/alias + occurrence neighborhood fingerprint + occurrence ordinal`，具体算法由你审慎决定。**不要只用行号/偏移量当作永久 ID**；也不要写稳定 ID 回 Markdown。对于重复完全相同的链接、文本大量编辑或重命名导致不再可辨别的情况，宁可丢弃对应手动位置并自动排布，也不能错配卡片。

- 程序启动时解析当前原生 Wikilink，只有实际存在的锚点才能应用保存的 UI 位置。
- 删除双链后不能从旧 UI 记录重新产生卡片。
- 笔记或目标文件重命名后的数据要有明确的安全迁移/失效策略；利用已有原生 rename 事件，不私自改写 Markdown。
- 为避免布局数据无限膨胀，实行大小/条数限制、去重、过期清理和容错读取，保存需 debounce，避免每次 `pointermove` 写磁盘；只在 drop 或必要的稳定时机保存。
- 设置提供「清除当前笔记布局」及「清除所有布局」并有适当确认；清除后双链完全保留。
- 文档清楚说明：**仅布局是插件数据，链接关系始终是原生双链；恢复旧版或删除 `data.json` 只会丢失自定义位置。**

### 3.3 卡片支持多形状、多风格、尺寸

至少实现：

1. `horizontal` 横向卡片：延续原有文件图标 + 名称/路径。
2. `square` 正方形卡片：例如默认 76–92px 方形，图标在上，简短名称在下，溢出省略，完整名称通过 tooltip 和 aria-label 可读；不同文件类型有辨识度。
3. `icon` 极简图标：约 32–44px，可通过悬停与键盘获得完整文件路径。

进一步提供：

- 卡片尺寸（小、中、大）/合理的宽高限制；圆角、边框、阴影强度等基本外观选项。
- 图标遵循当前已有文件类型识别：Markdown、Canvas、HTML、PDF、图片、音频/视频、未知文件等；不要为了样式破坏现有特殊文件打开能力提示。
- 卡片风格跟随亮/暗主题，使用 Obsidian CSS 变量；不能直接写死浅色背景。
- 可以按文件类型显示对应图标，**不要把实际未解析文件伪装成可打开的已解析文件**。
- 统一设置适用于所有卡片即可，不需要每个卡片单独存颜色/类型。布局变化后重新计算卡片宽高、碰撞和连线端点，不得让 CSS 尺寸与布局模型不一致。
- 窄边距下自动退化到紧凑图标或暂不显示，绝不遮挡正文；切换样式后已保存的自由坐标要合法化与安全裁剪。

### 3.4 更完整的设置中心 + 快捷控制入口

**必须保留原生 Obsidian 设置页**，不要另造一个难维护的完整应用框架。重构 `src/ui/settings-tab.ts`，按功能分组展示，优先用 `PluginSettingTab`、`Setting`、原生 DOM 等公开 API。

建议设置分组：

- **基础**：启用、自动显示、重置默认设置。
- **连线**：隐藏/悬停/常驻；曲线/直线/折线；粗细；透明度；主题色/预设色。
- **布局**：自动/自由/吸附；左右优先；边缘留白；吸附强度/间距（可先实现最少必要配置）；当前笔记重置/全局重置。
- **卡片**：横向/正方形/图标；尺寸；圆角、边框、阴影；是否显示文件名或路径（按卡片类型合理控制）。
- **交互与辅助功能**：悬停反馈、拖动提示、减少动画与可访问性说明；不必所有高级选项都立刻实现，未实现的不要显示成可操作设置。

在设置页加一个**轻量实时预览**（可用静态 DOM/SVG 小样，不依赖外部框架）：修改连线粗细、形状、颜色或卡片形状时立即反映，不需要切回笔记才能确认。预览不能修改用户笔记。

再增加**轻量快捷控制面板**：

- 通过 Obsidian Ribbon 或命令面板提供「打开 MarginLink 快捷控制」。避免堆满 Ribbon 图标；只增加一个可选入口。
- 快捷面板提供最常用的：插件显示开关、连线常驻开关、当前布局模式、卡片样式、重置当前笔记布局、跳转完整设置。
- 可以用 Obsidian 原生 `Modal` 或轻量 popover；**不能侵占用户原有大面积侧边栏**。如确实需要自定义侧边面板，请作为可选方案，不是默认强制打开。
- 所有开关与原生设置页共用一份偏好状态，操作立即生效并持久化；不能产生互相覆盖的状态源。

## 4. 本轮必须处理的兼容性和体验问题

1. **旧用户数据迁移**：旧版 `enabled / lines / density / layout` 的值要原样安全读取，原有偏好不可丢。为新增选项设置明确默认值；迁移后的旧布局语义应尽可能一致。`layout` 旧有值代表左右偏好，新布局模式应单独命名，例如 `placementMode`，避免名称冲突。采用显式版本化 schema 或可靠的读取白名单，不能盲目信任 `loadData()`。
2. **设置页文案更新**：当前设置页写着「卡片坐标不会持久化」，本版保存坐标后必须修改。README 的对应边界、人工验收与发布说明也必须同步。
3. **Live Preview、源码模式、阅读模式**：均需呈现卡片和连线；创建双链仍遵守原来只在安全编辑选区执行的限制。拖卡片时不能修改 CodeMirror selection 或触发原有新建关联手柄；阅读模式也应允许移动文件卡片（如技术上可安全实施）。
4. **窗口和空间**：支持限制行宽打开/关闭、打开侧边栏、宽窄窗口、长文滚动、分屏、多个打开文件、同一文件不同 leaf；各视图的卡片不应绘制到别的 pane 或遮盖正文。
5. **交互冲突**：卡片点击打开、Ctrl/Cmd 新标签打开、文件 hover、Tab/Enter 键盘操作、正文原生双链跳转及原本拖动选区建链必须保持正常。不要禁止全局文字选择。
6. **插件卸载**：全部 overlay、SVG、全局监听、Observer、pointer capture、CSS class 清理；不能留下幽灵卡片或泄漏事件监听。
7. **HTML 等特殊格式**：沿用当前仅展示真实 Vault 可解析目标、缺查看器安全提示的方案；不在这次任务里实现任意 HTML 运行器，也不以转换文件格式解决问题。
8. **性能**：一次文档中几十乃至上百个链接时避免明显卡顿；仍沿用视口裁剪、`requestAnimationFrame` 合并重排；防止自己的 DOM/CSS 变更导致 `MutationObserver` 无限刷新；不要在每帧重新读写整个笔记或全量重建所有 DOM。
9. **无障碍**：拖拽之外提供可键盘触达的恢复自动位置/重置命令；卡片与快捷面板有文字标签；提示信息可理解；减少动画设置应被尊重。
10. **版本管理**：将 package / manifest / version docs 更新为一致的合适 `0.2.0` 版本；如果发布规则需要额外处理版本兼容范围，请按实际项目惯例执行，不要虚构已发布的 Release。

### 5.2 数据保存安全

以现有 `loadData()/saveData()` 为唯一持久化接口，数据 schema 示例（仅示意，不得机械套用）：

```ts
interface StoredDataV2 {
  schemaVersion: 2;
  preferences: {
    enabled: boolean;
    lines: 'none' | 'hover' | 'always';
    lineStyle: 'curve' | 'straight' | 'elbow';
    lineWidth: number;
    lineOpacity: number;
    lineColor: 'theme' | 'purple' | 'blue' | 'green' | 'gray';
    placementMode: 'auto' | 'free' | 'snap';
    sidePreference: 'balanced' | 'left' | 'right';
    cardShape: 'horizontal' | 'square' | 'icon';
    cardSize: 'small' | 'medium' | 'large';
    // 其他明确的纯 UI 配置
  };
  layouts?: Record<string, unknown>; // 仅 UI 位置，须验证、限额与安全恢复
}
```

可设计更严格的数据结构。不要在 `layouts` 内偷偷存另一套关系图谱：**记录的存在不能构成链接，必须在当前 Markdown 里找到真实 Wikilink 才能显示卡片**。不要把整个笔记正文存入 `data.json`；弱身份指纹应仅含最小必要、稳定的哈希或短上下文，不要存长篇内容。对用户可能包含敏感文字的锚点，优先散列而非明文复制。使用稳定的非密码学哈希仅作为匹配提示即可，避免将其误认为绝对唯一 ID；歧义时失效。

### 5.3 相对坐标与连线

卡片几何计算必须有明确的坐标系，例如全部统一为 `MarkdownView.contentEl` 局部坐标：

- 锚点由 `DOMRect` 转换到局部坐标。
- 左右空白带由正文边界与当前滚动视口边界求交得到。
- 拖放的局部坐标转换成可保存的相对值。
- 重新渲染时从锚点和当前空白带恢复坐标，随后执行裁剪/吸附/碰撞处理。
- 连线终点取卡片真实最终位置，而非拖前的位置；不同线型共享相同端点约束。
- 当卡片不可安全显示时，隐藏卡片及对应连线，不显示指向虚空的 SVG。

不要给整个编辑区施加 `transform`、`overflow` 或强制宽度来制造空白区，更不能挤压 Obsidian 现有布局。

### 5.4 可测试性

布局、存储迁移、弱 ID 匹配、线型路径、坐标约束、碰撞/吸附尽量是可独立测试的纯函数。渲染层只负责桥接 Obsidian API、DOM 和行为。

## 7. 推荐交互验收脚本（人工在真实 Obsidian 操作）

1. 打开含 `[[References/product_release_stages.html|Early Access]]` 的笔记；关闭插件再打开，原生双链仍在，卡片恢复。
2. 设置连线「始终显示」，调粗细、透明度和线型，观察正文右侧连接线即时变化，换主题也清晰可读。
3. 将同一张卡片从左侧上方拖至左侧下方，连线跟随，松手固定；滚动时卡片仍合理跟随对应文字。
4. 将卡片拖至右侧，重启 Obsidian、重开此笔记，位置在可用边距内合理恢复；如果窗口显著变化，自动安全裁剪而非遮挡正文。
5. 选「正方形」显示，图标/名称排布正确；切「横向」和「极简图标」后不卡死、连线终点正确。
6. 打开快捷控制面板切换常驻/布局/样式，与设置中心相互同步；重置当前笔记位置，其他笔记布局不受影响。
7. 原文字选区拖到边缘创建双链，验证最终 Markdown 恰为 `[[文件路径|原文字]]`；本次新建双链与已有卡片拖动没有行为冲突。
8. 生成多处相同的 `[[Note A|同一句话]]`，逐个拖到不同位置；编辑前文后不能产生错链或乱跳卡片。
9. 删除某条原生双链后，即使之前保存了它的位置，也没有残留的幽灵节点。
10. 分屏、改窗口宽度、显示/隐藏侧边栏、改限制行宽和字体，确认不覆盖正文、其他面板及原生按钮。
11. 删除 `data.json` 或执行全局布局重置，链接关系和笔记内容完全不变，只失去个性化样式/位置。
12. 禁用插件，所有卡片、连线、附加类和快捷面板消失，Obsidian 原生操作正常。
