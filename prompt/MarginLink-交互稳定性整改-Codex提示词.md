# MarginLink 交互稳定性整改｜Codex 执行提示词

请在现有 [DewMysimple/MarginLink 仓库](https://github.com/DewMysimple/MarginLink) 直接完成以下四项整改，交付经过测试的可安装插件。先读取仓库的 `AGENTS.md`，核对当前分支、工作树与已有实现。分析基线是 **v0.2.1，提交 `15ee229`**。如果分支已更新，请按当前代码复现，只修改仍有问题的路径。

我希望这样使用插件：拖动 Obsidian 右侧栏的分隔线，正文旁的卡片与连线平稳跟随；悬停一张卡片，只看到文件名和类型；抓住卡片右上角开始移动，鼠标始终抓在那个角上；松手后卡片就地放好，拖动途中没有提示文字遮住视线。

## 1. 拖侧栏时连续更新卡片和连线

- 同一笔记、同一个可见锚点、边距足够时，拖动左右侧栏或分屏分隔线的全程都应看见卡片。开启常驻连线后，线头应在同一帧连到该卡片的新边缘。尤其要测“拉一下，停一下，继续拉，鼠标始终没松开”。
- 容器与正文尺寸变化时，在当前 Markdown 视图内合并刷新。观察器可只请求下一帧，在渲染中集中读取正文、视口、锚点与宿主的几何值，再同步更新卡片和 SVG。复用已有卡片节点，检查每张卡片绘制时重复读取宿主矩形的路径。避免用全层隐藏、增大防抖、等鼠标松手才恢复，或延长淡入动画掩盖闪烁。
- 空间确实不足时沿用现有自适应规则：仅让受影响的卡片缩成图标，连图标也放不下时才隐藏该张卡和对应连线。宽度恢复后恢复原先样式与相对位置。如果定位到临界宽度处的反复切换，可为恢复较大形态设置小幅余量；缩小时始终服从真实可用边界。正常滚出视口、切换文件时的来源校验继续生效。
- 拖分隔线不应启动卡片拖动，不应写入新的卡片位置。分屏单独计算，保留正文防遮挡、侧栏隔离和上版的 A → B → A 布局恢复。插件空闲后停止重排，卸载时释放观察器、监听器和已排队的帧。

## 2. 卡片悬停只显示“文件名称 · 文件类型”

- 对正文边缘的链接文件卡片，全屏最多只为当前悬停卡片显示一个 MarginLink 提示。例如正文别名是 `Early Access`，目标是 `详细分析/Attachments/product_release_stages.html`，悬停只显示 **`product_release_stages.html · HTML 文件`**。保留文件扩展名，去掉目录、标题/块子路径、正文别名的重复、操作指导和解析诊断。卡片表面的现有别名继续正常显示。
- 已解析目标从 `TFile.name` 和扩展名取值。未解析目标从原生链接目标中提取末段；已知后缀可显示类型，普通无后缀且未解析时显示“类型未知”。缺失目标的既有视觉标识和点击时的必要提示继续工作。覆盖无别名、长中文名、HTML、Markdown、Canvas、未解析链接，以及同文件的标题/块引用。
- 选用一个可见 tooltip 机制，检查宿主从属性自动生成提示的行为，消除同一张卡片的双层提示。用文本节点或安全属性设置文本，保留按钮简短可读的无障碍名称与键盘操作。移出、按下拖动、视图切换或卡片销毁时收起并清理待显示的提示。改动限定在 MarginLink 卡片，尊重正文原生双链的页面预览和其他 Obsidian 控件。

## 3. 拖动已有卡片时没有跟随文字

- 清理现有卡片拖动的 `.margin-link-position-ghost`、对应的文字更新和多余样式。包括“放下保存位置”“已对齐并避让 · 放下保存”“无可用位置 · 松手恢复”及初始操作说明。合法、吸附、非法、跨侧和取消的全过程，屏幕上都不出现这类气泡或替代通知。
- 用卡片本身的位置、连线、抓取光标和可选的空白区边界表达反馈。已有 `dragHints` 设置可继续控制视觉边界，中文标签相应改为“显示拖动边界”；开或关都不显示跟随文字。在非法区松手按原规则回到起点。真实提交失败仍可在操作结束后告知用户。
- 这里的对象是用鼠标移动**已有文件卡片**。`src/editor/drag-controller.ts` 另管“选中文字后拖到页边建立双链”。检查名称近似的 CSS 选择器和监听器，保留原生建链手势。

## 4. 从哪里抓住卡片，就从哪里拖

- 在 `pointerdown` 时记录实际卡片外框的 `getBoundingClientRect()`、指针 ID 与抓点。以同一套 CSS 像素坐标计算，勿取子元素局部的 `offsetX/offsetY`；鼠标落在 SVG 或文件名上也必须以整张卡为基准。保留约 5 px 的现有判定阈值，越过阈值的第一帧用最初按下点计算位移。
- 自由模式、同尺寸、没有碰撞或边界约束时，严格满足 **卡片左上角位移 = 指针位移**。一种可行算法：按下时记下抓点比例 `u = (clientX − rect.left) / rect.width`、`v = (clientY − rect.top) / rect.height`。在当前视图局部坐标里，候选左上角为 `(pointerX − u × cardWidth, pointerY − v × cardHeight)`。跨侧卡片尺寸变化时，使用目标侧实际尺寸恢复比例。尺寸无效应安全取消。
- 先用原始指针判断是否落在合法空白区，再基于抓点推出候选矩形，最后才执行边界约束、吸附及碰撞避让。自由模式不额外对齐；吸附只产生可解释的有限修正。设计时区分“鼠标命中哪里”和“卡片画在哪里”。方向键移动原本使用卡片中心坐标，保留其语义。
- `pointermove` 预览和 `pointerup` 的最后坐标走同一计算路径。连线端点、最终提交的相对位置、重新打开时的显示，均取自最终合法矩形。结束时只提交一次。实际拖动产生的那次 click 不能打开文件；随后真正的单击、Ctrl/Cmd 加单击和键盘打开仍然有效。保留 Esc、`pointercancel`、丢失捕获、失焦和卸载的清理。

**已复现的测试向量。** 自由模式，一张 84 × 84 px 的方卡左上角在 `(1200,200)`，在其相对位置 `(78,6)` 按下。指针从 `(1278,206)` 移到 `(1286,218)`，移动量是 `(+8,+12)`。在边距充足、无碰撞的情况下，正确的卡片左上角是 **`(1208,212)`**。v0.2.1 的实际布局函数给出 **`(1244,176)`**，正好多向右 36 px、多向上 36 px。请把这个用例加入回归，并补一个左下角用例来捕捉方向错误。

## 如何验收

先在改动前取得对照，再用同一组操作验证最终构建。现有 `scripts/desktop-v2.mjs` 的部分检查要等几何稳定 8 帧，且几何安全检查会跳过隐藏图层；`scripts/desktop-remediation.mjs` 虽覆盖图标、文件名和空白处起拖，但比较的是它已经得到的预览与松手结果。这两种测试可继续保留。以下断言必须观察**过程中**的表现，并使用独立计算的期望值。

| 场景 | 操作与通过标准 |
| --- | --- |
| 分隔线拖动中 | 在当前笔记放一张方卡，固定可见锚点，打开常驻线。真实按住右侧设置栏的分隔线，连续慢拖、快拖、暂停再拖和反向拖动；左侧栏或分屏再测一次。对边距始终充足的路径逐帧记录实际可见性、卡片边界和 SVG 端点。已可见的目标必须 **0 个无故隐藏帧**，线与卡片同步，卡片不越界。记录消失或 DOM 被移除也算一次失败 |
| 穿过空间阈值 | 用单调缩小再放大的轨迹经过“方卡 → 图标 → 隐藏”。每个必要转换只发生一次，空间恢复后回到原来的侧别及相对位置。侧栏调整前后的该卡片布局记录一致 |
| 真正的长悬停 | 分别悬停在 HTML 卡片的图标、标题和空白处，等待足以触发原生延迟提示。只见一个“文件名称 · 类型”。再移出、移入另一张卡、按住拖动，均无残留。DOM 属性检查与真实桌面目视或系统级截图结合；单看页面 DOM 不足以排除系统气泡 |
| 安静拖动 | 在提示设置开、关两种情况下，走过合法空白、吸附位置、正文非法区，再取消或放置。拖动期间没有跟随文本，悬停气泡已收起，可选边界与光标仍然有用 |
| 抓点与提交一致 | 在自由模式从四角、中心、图标、文字起拖，横向卡、方卡、紧凑卡均覆盖。分别检查阈值内、第一帧、连续移动、释放和重新打开。无约束时卡片与指针位移差每轴不超过 1 CSS px。另测吸附、跨左右边距和受边界限制的情形，以约束后的合法矩形为准 |
| 整体稳定性 | 一次快速连做“拉侧栏 → 从卡片右上角拖动 → 松手 → 单击打开 → 后退”。再覆盖 Esc、失焦、阅读/编辑切换、分屏、关闭重开和正常重启。不得出现误开文件、卡住的抓取光标、幽灵连线、位置复位或 Markdown 改动。重复打开/关闭面板和禁用插件后，无残留提示、事件或持续空转刷新 |

仅在仓库的隔离测试库中运行桌面验收。沿用现有 TypeScript、测试和打包流程：`npm ci`、`npm test`、`npm run lint`、`npm run build`、`npm run package`。可用真实 Obsidian 时执行 `npm run test:desktop`，扩展现有脚本记录必要的帧序列、首帧抓点坐标与长悬停证据。桌面宿主不可用时，完成可运行的检查，给出未验证项和可复现步骤，标明布局函数测试与实机观察的区别。

**交付范围。** 原生 Wikilink 继续作为唯一链接来源；沿用现有插件数据、右侧设置面板、整卡拖动和手动布局恢复。这四项均可在渲染及交互层修复。针对实测发现且能复现的相关稳定性问题一并处理，避免借机重写布局存储或扩展产品功能。更新受到影响的设置说明和验证记录。最后用中文逐项报告实际原因、改动文件、验证结果及可安装产物路径，并按仓库现有交付约定收尾。

## 追加任务｜默认设置、侧栏下拉框和顶部标题

以下第 5–7 项与前四项一起实施、一起验收。用户的验收路径是：首次启用插件，打开一篇已有双链且边距足够的笔记，无需悬停即可看到常驻连线和可自由拖动的正方形卡片；点击左侧 MarginLink 图标打开右侧栏，抬眼就能读出标题和每个下拉框的当前选项。

### 5. 统一首次启用与恢复默认时的三个值

| 设置 | 默认显示文字 | 存储值 |
| --- | --- | --- |
| 连线显示 | 始终显示 | `lines = 'always'` |
| 卡片布局模式 | 自由拖动 | `placementMode = 'free'` |
| 卡片形状 | 正方形卡片 | `cardShape = 'square'` |

**实现线索。** v0.2.1 的 `src/types.ts` 在 `DEFAULT_PREFERENCES` 和 `readPreferences()` 的枚举回退逻辑中各写了一遍原默认值。只改其中一处，会让首次载入与“恢复默认外观设置”出现不同结果。为这三个字段使用同一份默认值，检查 `src/core/layout-store.ts` 的首次读取、旧版平铺配置和当前嵌套配置，以及 `src/ui/settings-tab.ts` 的重置入口。

- 新安装、配置缺失或单个字段无效时，对相应字段采用上表默认值。已有合法值逐项保留，包括用户保存过的“悬停”“自动排列”“横向卡片”。从旧配置无法判断某个合法值是否被用户手动选过，升级时保留它；用户可以点“恢复默认外观设置”一次采用新组合。
- `placementMode` 控制拖动行为；`layout` 仍控制左右优先。原有卡片位置继续沿用现有布局记录。新默认形状在边距充足时呈现为等宽高方卡，窄边距照常按可用空间降级。
- 设置表单、快捷控制、预览与真实笔记应读取同一套偏好。原测试若专门验证“悬停显示”或“自动排列”，应在该用例中显式选择相应模式，另设用例验证新默认值。

### 6. 修复右侧栏下拉框折叠时只显示箭头

截图中，右侧栏已经较宽，“连线显示”“线型”等设置行右边仍只有一个小箭头框；同一画面中的开关、按钮和滑块则能显示。用户需要**在下拉框收起时直接读到当前值**，例如“始终显示”“平滑曲线”。逐一检查同表单里的连线颜色、卡片布局模式、左右优先、卡片形状等下拉项。

**先判定是值丢失还是文字画不出来。** `src/ui/settings-tab.ts` 已通过原生 `Setting.addDropdown()` 注册中文选项。打开设置面板后，检查实际显示的 `select` 的 `value`、`selectedIndex` 和选中文本，排除宿主用于测宽的副本。若值和文本正确，测量可见控件、控件容器、标签列的实际宽度，以及扣除内边距与箭头后的文字可用宽度；检查宿主内联宽度、flex 收缩、字体颜色/对比度和裁剪。分别观察侧栏从折叠状态首次打开、展开稳定后、选中较长文本后和拖窄再拉宽时的结果。现有 CSS 允许设置行换行并给说明列设置了最小宽度；这些是排查入口，具体根因以桌面复现为准。

- 保留原生下拉选择和键盘交互。宽面板中让名称与控件同排，给中文选中值和箭头留出实际空间；变窄时允许控件另起一行并利用可用宽度。样式限定在 MarginLink 的设置容器；不要用全局 `select` 覆盖、固定整栏宽度或额外重复一份静态文字来补救。
- 选择新的短项或长项后，折叠控件应立即显示新文字。改变侧栏宽度时，文字与箭头互不覆盖，表单不产生横向滚动。尤其验证较长的“悬停或聚焦时显示”。同时回归滑块数值、切换开关、重置按钮以及原生设置页里的共享表单。

### 7. 顶部标题精确显示 `MarginLink`

在共享设置表单 `renderSettings()` 中，将可见的顶部主标题从“MarginLink · 空间布局与外观”改为“MarginLink”，大小写如上。v0.2.1 的 `src/ui/settings-view.ts` 中，标签名 `getDisplayText()` 已经是 `MarginLink`。右侧栏与原生设置页都检查实际渲染的主标题；保留“基础”“连线”“布局”“卡片”等分组和已有控件。
