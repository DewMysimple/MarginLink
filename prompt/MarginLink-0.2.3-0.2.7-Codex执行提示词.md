## 0.2.3　连线接入文字边界的中点

**目标画面**　正文里有一个别名为 `Scene Graph` 的链接。卡片在它右侧时，连线可从文字右边缘的垂直中点出发；卡片正上方时，连线可从文字上边缘的水平中点出发。卡片在左、下方时同理。文字区块指本次链接实际显示的文字，包括别名。端点应贴边，字形清晰可读。

- 从 `src/editor/editor-extension.ts`、`src/reading/reading-anchors.ts`、`src/view/margin-overlay.ts`、`src/view/connector-renderer.ts` 追踪几何数据。基线实现会取最后一段文字矩形，绘制时用 `rect.bottom + 2` 定纵坐标。将“用于排布卡片的位置”和“用于画线的端点”分别计算，避免升级后已保存的卡片发生位移。
- 以同一坐标系内的可见文字矩形和卡片边框计算候选端点。单行取文字四条边的中点，卡片也从合适的边界中点接入。自动换行时按实际可见的文字行片段计算；同一视觉行的相邻片段可合并。候选点必须落在有文字的一段上。相同目标在正文出现多次，分别从各自出现的位置出线。
- 优先让线从文字边界向外出发、从卡片外侧接入，避开链接文字和卡片内部，然后比较路径长度与转折。曲线的切向、折线的第一段和最后一段都应服从端点方向。两个方案近似时沿用当前边，避免侧栏宽度轻微变化时来回换边。滚动、换行、缩放与自由拖卡时更新可见连线，复用现有绘制调度。
- **验收**　在实时预览和阅读视图中，把同一张卡片分别拖到链接左、右、斜上和斜下，再构造卡片明显位于文字正上、正下的几何用例。确认四条边都能被选中。再用跨两行的长别名、同词重复出现、曲线和折线各验一次。缓慢拖动侧栏分隔条时卡片和连线稳定，切回笔记后保存的位置正确。

## 0.2.4　HTML 文件图标直接显示四个字母

- 在 `src/view/card-renderer.ts` 的现有文件类型分派处处理 `.html` 与 `.htm`，扩展名大小写一致处理。使用带清晰大写 **HTML** 字样的图标。可采用简洁的文件轮廓和文字标记，并按实际可用尺寸调整图形比例。沿用主题前景色，图标随插件打包。
- 卡片标题继续显示链接别名。例如 `[[Attachments/product_release_stages.html|Early Access]]` 的卡片标题是 `Early Access`，从图标上能直接读出 `HTML`。悬停沿用“文件名 · 文件类型”，保留未解析文件提示与现有打开行为。
- **验收**　测试 `.html`、`.htm`、`.HTML` 和一个 Markdown 对照文件。在正方形卡片及现有紧凑布局、亮色与暗色主题、100% 缩放下检查。最小卡片上的四个字母仍能分辨，标题和图标各有空间。

## 0.2.5　精简选中文字后的拖拽提示

- 本版调整选中文字后浮现的链形手柄。在 `src/editor/drag-controller.ts` 核对按钮上的 `title`、Obsidian 可能显示的无障碍提示、拖动浮层和落点文案。鼠标静置时最多显示一个提示，文字为 **关联文件**。可借鉴卡片已有的 `aria-labelledby` 实现，确保按钮在无障碍树里仍有可读名称。
- 拖动开始即收起提示，有效页边只用高亮表示可放下。移除“链接到已有文件”“放下以选择文件”等跟随文字。释放、Esc、失焦或取消后清除本次高亮。手柄的 Enter／Space 键和原有命令继续可用，0.2.5 单独安装时仍能完成已有文件关联。
- **验收**　悬停到系统提示通常出现的时长，确认没有第二个气泡。连续测试鼠标拖动、键盘激活、拖回正文取消；每次只触发一次相应操作。另验已生成的文件卡片仍可整卡拖动，从卡片边角起拖时抓取点稳定，卡片悬停仍能读到文件名和类型。

## 0.2.6　已有文件、新建笔记与打开方式

### 入口与目录设置

1. 在 Markdown 编辑器中选中文字，将链形手柄放到有效页边，弹出一个操作面板，明确提供 **已有文件** 和 **新建文件**。初始进入已有文件搜索，可直接输入文件名或路径。键盘激活手柄及既有“将选中文字链接到文件”命令进入同一流程。放到无效区域或在提交前取消，正文、目录和文件均无写入。
2. “已有文件”复用现有 Vault 文件搜索、目标校验和写入逻辑，支持 Markdown、HTML 等已有类型。选择后生成原生双链，回到原文。“新建文件”默认创建 Markdown，显示文件名、目标目录和 **创建并链接** 按钮。以选中文字预填文件名，允许修改；链接显示文字始终取最初选区。输入 `model-assisted` 或 `model-assisted.md` 均得到一个 `.md` 后缀。
3. 在现有 MarginLink 设置面板加入 **新建笔记存放位置**。提供三个可配置的当前 Vault 文件夹位置，可指定其中一个作为默认。在创建面板显示实际目录，并允许本次切换到另一个已配置位置。三个位置全未配置时，明确显示并使用“仓库根目录”。已选的具体目录被移动或删除时，能可靠跟踪就更新，否则请用户重选，再允许创建。目录选择仅影响本插件。
4. 用户确认前展示最终目标路径。校验空名、目录穿越、路径分隔符以及无法安全表示为原生 Wikilink 的文件名或别名。遇到同路径文件，提供“使用已有文件”或修改名称的选择，保留原文件内容。只有用户确认创建本次目标时才写入文件。

### 最终点击决定是否打开新窗口

| 用户在“新建文件”面板的操作 | 原笔记 | 新笔记与焦点 |
| --- | --- | --- |
| 普通点击“创建并链接”，或普通 Enter 确认 | 用一条双链替换原选区，保留原窗口、滚动位置，光标落在链接之后 | 笔记已创建，焦点回到原文，可直接接着输入 |
| 按住 Ctrl 点击“创建并链接” | 在同一原选区写入同一条双链，原文保留在原窗口 | 立即打开一个独立的 Obsidian 桌面窗口，显示刚创建的笔记并获得编辑焦点 |

- 在最终确认按钮的点击事件中同步读取 `event.ctrlKey`，在第一个异步操作前固定本次打开方式。拖拽时是否按 Ctrl、进入“新建文件”时是否按 Ctrl、文件写入期间何时松开 Ctrl，都不改变最终点击已选定的行为。这条规则只属于“创建并链接”。
- 先完成创建及原文事务，再用 Obsidian 公共 API 把本次创建返回的 `TFile` 打开在新的独立窗口。可用 `workspace.getLeaf('window')` 获取该窗口的 leaf，调用 `leaf.openFile(file)`，再按当前 SDK 设置活动 leaf 和焦点。关闭创建面板后要验证实际前台窗口及编辑焦点，防止焦点被晚到的回调拉回。需要用户再点一下才能输入，视为未通过。[Obsidian 官方 API 类型声明](https://github.com/obsidianmd/obsidian-api/blob/master/obsidian.d.ts)
- 界面要能发现此操作。在创建面板确认按钮旁放一行静态短提示，如 **Ctrl + 点击可在新窗口打开**。这行只出现在最终确认处。

### 原生双链和异常处理

- 从 `src/editor/selection-action.ts`、`src/ui/file-picker.ts`、`src/core/link-formatter.ts`、`src/core/link-resolver.ts` 入手。保留源笔记、编辑器实例、选区范围、原选文字及版本检查。创建前检查一次；异步创建返回后，原文写入前再检查一次。焦点暂时进入面板是正常流程，用户真正切换源笔记、改变选区或改写原文时应终止过期操作。
- 新文件链接使用 **实际 Vault 根目录相对路径，含扩展名，后接原选文字作为别名**。以 `详细分析/Vocabulary` 为目标目录，选中 `model-assisted`，验收时原始 Markdown 必须逐字为 `[[详细分析/Vocabulary/model-assisted.md|model-assisted]]`。若用户将文件改名为 `model-assisted-notes`，结果必须是 `[[详细分析/Vocabulary/model-assisted-notes.md|model-assisted]]`。使用既有格式化和校验逻辑。以创建返回文件的身份及路径校验本次目标，允许正常的索引更新时间，避免同名文件被误连。
- 只替换选区一次，使用一次可撤销的编辑器事务。一次撤销可恢复原选文字。文件关系全部保存在原生 Wikilink 内；三个目录预设与既有布局偏好保存在插件原有设置数据中。
- 提交期间防重入，区分双击、重复 Enter、窗口失焦与真正取消。若创建失败，留在面板并保留输入；若已建文件但原文已失效，保留刚建文件并明确显示路径，源笔记不落错链；若仅打开新窗口失败，保留已成功创建的文件与原文双链，提示目标路径，重试打开时复用该文件。

### 桌面验收场景

| 操作 | 通过条件 |
| --- | --- |
| 普通创建后立即输入一个字符 | 字符出现在原文的双链后方，窗口数量与操作前相同 |
| 最终点击时按住 Ctrl，点击后即松开 | 仅增加一个可独立移动的 Obsidian 窗口；新笔记立即可输入；返回原窗口可见精确双链 |
| 拖动手柄时按 Ctrl，最终普通点击 | 按普通创建处理，焦点回到原文 |
| 连续双击确认，或连续发送确认按键 | 仅一个目标文件、一次替换；需要开窗时仅开一个 |
| 分别用三个预设目录、未配置的根目录和一个已删除的预设 | 文件位于预期目录；目录失效时允许重选；设置在重启后保留 |
| 不同目录已有同名文件、目标目录已有同名文件、模拟新文件索引稍晚 | 精确链接到本次目标；已有同路径文件保留内容；索引延迟不会生成另一个文件 |
| 取消、切换源笔记、创建失败、原文写入失败、开窗失败 | 按上文对应阶段检查文件、原文和窗口数；任何情形都能定位已创建的文件 |

## 0.2.7　让原生文件列表识别 HTML 与 XMind

**完成标准**　在独立测试库里关闭 Obsidian 的“显示所有文件类型”。启用 MarginLink 后，用户能够在原生侧栏文件列表展开文件夹，看见已有的 HTML 网页与 XMind 思维导图，选中它们，并用 MarginLink 生成指向原文件的 Wikilink。用户不必先写链接，也不必先打开该文件。

### 公开设置

在现有设置表单添加分组 **Obsidian 能识别的文件类型**。左侧 Ribbon 打开的设置面板和 Obsidian 设置中的 MarginLink 页面共用同一份偏好。设置页标题继续显示 MarginLink。

| 设置开关 | 对应扩展名 | 首次启用或从旧版升级时 |
| --- | --- | --- |
| HTML 网页 | `.html`、`.htm` | 默认开启 |
| XMind 思维导图 | `.xmind` | 默认开启 |

两个开关可单独保存，写入插件已有的设置数据，保留其他显式偏好与已保存的卡片位置。设置显示实际生效时机。如果目标 SDK 只支持在插件生命周期结束时释放扩展名关联，切换后立即保存，并就地提示“重新加载 MarginLink 后生效”。明确操作是去“第三方插件”关闭再启用 MarginLink。用户切回当前生效值时应清除待重载提示。关闭开关会撤回本插件对该类型的识别；原生“显示所有文件类型”和其他查看器各自仍然生效。

### 实现依据与文件打开

1. Obsidian 官方说明，插件通过 `Plugin.registerExtensions()` 可在全局“显示所有文件类型”关闭时声明其支持的扩展名。使用项目锁定 SDK 的公开 `registerView`、`registerExtensions`，以独立的注册操作处理 `html`、`htm`、`xmind`。依靠宿主更新原生文件列表，保留宿主的排序、折叠、重命名和文件菜单。保持用户的全局设置原值。[官方变更说明](https://obsidian.md/changelog/2021-01-25-desktop-v0.10.10/) · [原生文件设置](https://obsidian.md/help/settings) · [官方支持的格式](https://obsidian.md/help/file-formats)
2. 已有查看器占用扩展名时，保留已有处理器，逐项处理注册失败；区分可证实的冲突和普通错误。一个后缀失败时，继续处理其余后缀。避免接管未知扩展名或修改私有注册表。若某个查看器后来才加载，允许用户关闭本插件对应开关并重载，以选择该查看器。
3. 原生文件列表与 MarginLink 卡片点击同一个目标时，均应能打开确切的文件。没有专门查看器时，提供可恢复的轻量只读附件页，显示真实文件名和类型。用户可通过原生文件菜单的“在默认应用中打开”交给浏览器或 XMind。点击或恢复附件页时无需执行 HTML、解包脑图或启动外部进程。真实附件保留原始扩展名和字节。把插件当前成功注册的后缀纳入既有打开能力判断，即使附件视图从未打开，首次点击卡片也能成功。[原生文件列表与菜单](https://obsidian.md/help/plugins/file-explorer)
4. “已有文件”搜索和正文写回继续由现有流程处理。测试 `[[资料/Early Access.html|参考网页]]`、`[[导图/项目规划.xmind|项目规划]]`。文件菜单显示实际文件，HTML 卡片沿用四字母图标，XMind 悬停显示文件名和可辨认的文件类型。0.2.6 的“新建文件”仍创建 Markdown，其 Ctrl 点击规则只作用于最终的“创建并链接”。

- 准备已有的 `资料/Early Access.html`、一个 `.htm`、可由 XMind 打开的 `导图/项目规划.xmind` 和一个未知后缀作为对照。在全局“显示所有文件类型”关闭、没有其他相关插件时，分别验两个开关的开/开、开/关、关/开、关/关。逐项检查原生文件列表中的实际条目及可打开性。插件自己的文件选择器只能验证搜索功能。

## 验证与交付

- 一个补丁对应一个可独立安装并验证的版本。逐版更新项目约定的版本文件及变更记录；核对 `manifest.json`、`package.json`、锁文件和 `versions.json` 的实际用途。按仓库脚本运行 `npm test`、`npm run lint`、`npm run build`、`npm run package`。后一版打包前保留前一版安装包或压缩副本，标明版本。
- 对容易复发的行为补针对性测试，包括四向端点与换行、确认时的 Ctrl 状态、同名路径与索引延迟、重复确认及事务失败。涉及视觉、拖动、前台独立窗口和焦点的断言在仓库指定的隔离 Obsidian 桌面环境验收。用普通点和 Ctrl 点各实际输入一次来区分焦点归属。
- 回归既有体验：默认始终显示连线、自由拖动、正方形卡片；用户已有偏好继续生效。确认切换笔记后的布局、侧栏伸缩时的画面稳定、设置入口、原标题 `MarginLink` 及现有卡片点击行为。
- 按仓库交付约定为五个版本分别提交，核对当前 upstream 并记录同步结果。最终列出实际版本、提交 ID、安装包位置、测试结果，以及桌面上亲自验证过的场景。若桌面环境缺失，明确留下未实测项和复现步骤，区分自动化通过与真实窗口验收。
