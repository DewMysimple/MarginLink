>
> **交付要求**：请直接编写、测试、构建一个可安装、可使用的 Obsidian 桌面社区插件。不要仅输出方案、伪代码、效果图、静态 HTML 或待办清单。

## 1. 背景与核心体验

Obsidian 打开 Markdown 笔记并启用“限制行宽”（Readable line length）时，正文通常位于中间，左右会留下较大空白。希望充分利用**同一篇笔记内部**的这些空白：把正文里的双链显示成旁边的文件图标或文件卡片，并用可见的曲线关联到具体的双链文字。

概念示意（仅用于解释交互，不是必须完全复刻的像素设计）：

```text
┌───────────────────────────── Obsidian Markdown 笔记区域 ─────────────────────────────┐
│                                                                                      │
│  左侧边缘空白             限制行宽的正文                   右侧边缘空白               │
│                                                                                      │
│                        Building this together                                        │
│                                                                                      │
│                        We'll have a lot more to share                                │
│                        on the road to [Early Access] ────────╮                      │
│                                                              ╰──→ [🌐 HTML 卡片]      │
│                        Here is the [[技术方案]] ──────╮                              │
│                                                      ╰────→ [📄 MD 卡片]              │
│                                                                                      │
└──────────────────────────────────────────────────────────────────────────────────────┘
```

核心感受：

- 不打开新的侧边栏、不切换到全局关系图谱、不覆盖正文。
- 正文保持正常阅读；笔记两侧出现与具体文字一一对应的文件节点。
- 通过视觉连线，一眼知道“这句话连接了哪个文件”。
- 不必先用拖拽建立关系：**已有原生双链要自动被展示**。
- 可以选中文字，把选区拖到正文左侧或右侧的空白里，然后在文件选择器中选取目标文件；完成后自动形成原生双链，并立即出现卡片和连线。
- 关闭或卸载插件后，Markdown 中的所有原生双链仍然存在并可正常使用。

## 2. 无条件遵守的产品约束（NON-NEGOTIABLE）

### 2.1 原生双链是唯一的关联来源

只识别或生成 Obsidian Wikilink，典型形式：

```md
[[目标笔记]]
[[项目/目标笔记.md|显示名称]]
[[项目/产品路线图.canvas|产品路线图]]
[[References/product_release_stages.html|Early Access]]
[[设计文档#方案讨论|方案讨论]]
[[设计文档#^block-id|关键段落]]
```

例如用户选中 `Early Access` 并选择 `References/product_release_stages.html`：

操作前：

```md
We'll have a lot more to share on the road to Early Access, including deep dives...
```

操作后，**只修改所选文字对应的 Markdown**：

```md
We'll have a lot more to share on the road to [[References/product_release_stages.html|Early Access]], including deep dives...
```

边缘卡片和连线仅根据该双链实时渲染，不额外保存关系。

### 2.2 严禁引入自定义关联数据结构的持久化

**禁止**为了记录文字与文件的关系而创建或修改：

- `.marginlink.json`、`links.json`、`relations.json`、`.marginlink/` 或任何关系清单、边文件、sidecar 文件。
- YAML frontmatter 中的关联属性。
- 额外的 HTML 注释、专用 Markdown 标记、隐藏锚点、不可见 ID、`data-*` 标识写回笔记。
- 外部 SQLite/IndexedDB/localStorage 数据库或云端关联服务。
- 对用户的文件做自动复制、导入、转换，或生成替身 Markdown 文件。

**允许**：在运行时内存中临时构造 `{sourceRange, linkTarget, cardPosition}` 等渲染数据；使用 Obsidian 官方插件 `loadData()/saveData()` **只保存纯界面偏好**（例如是否显示连线、卡片尺寸、左右侧布局模式）。不得在插件设置中保存文件路径、链接坐标、每条链接的 ID 或关联映射。

### 2.3 关于左右拖拽位置的重要限制

原生双链本身不记录“卡片放在左边还是右边”或“卡片的具体坐标”。因此：

- 用户拖到左/右空白区时，可以在**当前会话**中先把新卡片显示在对应一侧。
- 重新打开笔记或重启插件后，必须按照**可重复、确定性的自动排版算法**重新分配两侧位置。
- 不允许为了永久记住拖放位置，偷偷增加自定义 Markdown 或其他关联数据。
- README 必须明确解释：**双链关系永久保存，卡片的空间布局不承诺跨会话固定**。

### 2.4 不强制改变 Obsidian 原生行为

- 不强制用户打开或关闭“限制行宽”。只根据实际可用空间调整布局。
- 不覆盖原生双链的点击、悬停预览、重命名更新、撤销/重做等功能。
- 不在全局编辑器中修改其他类型的链接。首版只可视化 **Wikilink 非嵌入式双链**；普通 Markdown 链接 `[文本](目标)`、外部 URL 和 `![[...]]` 嵌入式链接不得被错误地当成目标卡片。
- 不将整个笔记转换为 Canvas，不创建新 Obsidian View / 右侧停靠面板来替代主方案。

## 3. 第一版必须完成的功能（MVP/P0）

### 3.1 自动识别已有双链并在边缘可视化

打开已有双链的 Markdown 笔记后：

1. 无需用户预先运行任何“建立索引”命令。
2. 找到正文中符合条件的原生 Wikilink，定位其在当前显示模式中的**实际文字渲染位置**。
3. 在笔记内部的左/右空白区创建一个对应的文件图标或紧凑卡片。
4. 用曲线从文字附近连接到对应卡片；颜色采用 Obsidian 主题的 accent 变量，而非写死紫色。
5. 卡片展示目标文件类型图标、显示名称或文件名，必要时展示相对路径；不要在卡片中执行文件内容。
6. 正文中同一文件被引用多次时，按**每一次双链出现**生成独立可识别的关联（不要丢失具体文本位置）。
7. 已有标题/块引用链接 `[[note#heading|alias]]` 应保留原始目标与子路径，不得截断为普通文件链接。
8. 文件缺失、重命名暂未更新或链接无法解析时，展示明确的“未解析”视觉状态，而不是随便映射到同名文件。
9. 只有当前 Markdown 文档所在的 leaf/pane 显示其自己的卡片；分屏时彼此不串联、不串位。

### 3.2 两侧边缘布局，不创建独立侧边栏

- 把渲染图层挂载到**当前 Markdown 视图**的合适容器中，通过 scoped DOM、定位层和 SVG 实现，不能挂到全应用绝对坐标上导致分屏串位。
- 根据编辑器/阅读区容器宽度与正文内容宽度，计算左右真实空白宽度。
- 宽度充足时显示文件卡片；边缘较窄时自动使用紧凑图标/小标签；再窄时安全隐藏或提供轻量的展开入口，不能遮盖正文或水平溢出。
- 优先把卡片放在距离文字较近的一侧，并尽量均衡左右边缘；对同侧卡片采用有最小间距的防重叠算法。
- 连线使用 SVG path 或同等级方案，端点与文字、卡片对应；支持跨多行自然折行产生的坐标变化。
- 正文正常滚动时，卡片和连线跟随当前可见锚点；不可见锚点不应产生漂浮的错误连线。
- 视图尺寸变化、侧边栏开关、窗口缩放、主题更换、行宽选项改变、分屏调整、字体大小与段落重排后及时更新。
- 不抢正文鼠标滚轮、文本选择、输入焦点；overlay 的非交互部分必须合理使用 `pointer-events: none`。
- 用户打开两个标签/两个独立阅读视图也应正常运行；切换笔记时清理旧卡片与 observer。

### 3.3 默认的视觉与交互体验

- 默认“常驻轻量文件图标/卡片；悬停、选中或聚焦时高亮当前连线”，可以设置“始终显示连线 / 悬停显示连线”。
- 悬停正文双链时，高亮对应卡片和曲线；悬停卡片时，高亮正文双链；鼠标离开自动恢复。
- 点击卡片时，使用 Obsidian 支持的官方导航/打开方式打开目标；若目标不可打开，只提示能力限制，不自动生成新笔记或触发错误的文件创建。
- 保留原生链接的正常点击及页面预览行为。
- 当同一个文件名有多个同名目标时，优先展示足以区分它们的路径信息。
- 对暗色、亮色主题均可读；跟随 Obsidian CSS 变量，尽量融入原生 UI。
- 卡片须有 keyboard focus、aria-label、title/tooltip；支持键盘激活。

### 3.4 “选中文字 → 拖到空白区 → 选择文件 → 生成双链”

在 Live Preview 或源码编辑模式中，至少实现以下完整交互：

1. 用户用鼠标选择某段普通的行内文字，例如 `Early Access`。
2. 当有合法选区时，在选区旁显示一个低干扰的小型“链接拖拽手柄”；**不要截获用户正常选中文本的拖拽行为**。可通过拖拽手柄启动创建关联。
3. 用户从手柄拖动到正文左侧或右侧可用空白区域。拖动时显示轻量视觉反馈或半透明预览卡片；目标空白区域显示可放置的反馈。
4. 放下后打开 Obsidian 风格的文件搜索/选择界面（例如官方的 `FuzzySuggestModal<TFile>` 或适当的替代），选择**已经存在的文件**；支持搜索文件名、路径，优先使用 Obsidian 已识别的 Vault 文件列表。
5. 确认目标后，在选区原位置把文字替换为 `[[目标路径|原选中文字]]`，通过 Obsidian 的编辑器事务/`Editor` 接口完成，尽量确保一个可撤销的操作。
6. 页面即时更新卡片和连线，当前会话可优先显示在用户放下的那一边。
7. 如果按 Esc、取消文件选择、把手柄拖出合法区域，则**笔记绝对不发生修改**。
8. 用户从开始拖动到结束选择文件期间，若选区文本、活动文件或编辑器内容发生变化，必须校验原选区仍有效；校验失败则中止并友好提示，绝对不能错误包裹另一段文字。
9. 如果用户选中已在双链内部的文字、跨多个 Markdown 块/包含换行的内容、代码块、内联代码、YAML、嵌入内容或会产生非法 Wikilink 的内容，第一版可以明确禁止并解释原因；绝不能生成破损 Markdown 或嵌套双链。
10. 不能悄悄丢弃原文字、标点或空格。中文、英文、Unicode 和中文文件路径至少应按合法 Wikilink 规则正常处理；遇到 `|`、`]]` 等破坏别名结构的字符时明确阻止或提供安全的、不丢数据的处理方式。
11. 允许普通软折行；如果一次选区跨硬换行，第一版可明确禁止，但要给出说明。

**必须提供的备用方式**：即使用户觉得拖拽手柄难以发现，也可以通过命令面板执行“将选中文字链接到文件”，打开相同文件选择器，并生成相同双链。不依赖原生外部文件管理器的拖放事件来完成核心功能。

### 3.5 编辑器模式和阅读模式

至少支持以下场景：

- **Live Preview**：已有双链可视化；可选取文字并通过拖拽创建双链。
- **Source mode**：尽量显示双链对应的边缘节点；创建链接依然可用。视觉锚点在源码里可以定位到整个 Wikilink token，不必假装所有 Markdown 控制字符都不可见。
- **Reading view**：已有双链可视化、卡片点击打开目标。阅读模式不需要直接编辑文本，不能在阅读视图中模拟一个不可靠的选区编辑器。

阅读模式的 Markdown 会经过后处理，且可能按 section 渲染；要防止同一双链重复生成卡片。源码模式、实时预览与阅读模式的 DOM 结构不同，不能只给其中一个模式添加 CSS 就宣称三种模式全部支持。

### 3.6 与外部文件格式的兼容边界

官方原生支持的文件中包括 `.md`、`.canvas`、PDF、图片、音视频及其他若干格式。用户特别希望关联 `.html`，以及可能由其他社区插件处理的思维导图格式。

**重要现实限制**：`.html/.htm` 并非 Obsidian 官方默认原生支持的文件格式，某些专用思维导图扩展名也不受默认支持。因此：

- 保留并解析现有 Markdown 中的 `[[References/product_release_stages.html|Early Access]]` 原生 Wikilink 文本；能解析到的文件和不能解析到的文件必须在 UI 上有清楚区分。
- 通过 `Vault.getFiles()` / 原生文件解析机制提供文件搜索，不得声称 Obsidian 默认能索引或打开所有扩展名。
- 对未注册的 HTML 或特殊扩展名，如果原生 Vault/链接解析器无法找到它，卡片允许显示为“存在于双链文本中的未解析目标”；不得凭空说文件存在或可打开。
- 如果已安装相应文件类型处理插件并使 Obsidian 能识别/打开目标，则采用 Obsidian 的标准能力打开它；本插件**不承担实现 HTML 渲染器或思维导图编辑器**的责任。
- 不为 HTML 创建“影子 `.md` 文件”、隐藏映射、外部数据库或替代关系格式。
- 在 README 中清楚说明如何验证 `.html` 的可见性和可打开性，以及已安装文件类型插件与未安装时的行为差别。

### 4.1 唯一数据模型：从原生双链临时派生

可以使用仅存在于内存中的结构，例如：

```ts
interface WikilinkOccurrence {
  sourcePath: string;
  raw: string;                  // Markdown 原文中的 [[...]]
  startOffset: number;          // 当前文档中的字符偏移
  endOffset: number;
  targetLinktext: string;       // 含可选 #标题 或 #^block
  alias?: string;
  resolvedPath?: string;        // 可解析时的实际文件路径
  unresolved: boolean;
}
```

`startOffset/endOffset` 用于当前运行时定位，随着内容改变重新解析或映射；**绝不序列化为用户关系数据**。在阅读模式中，使用双链的源码位置、链接文字与实际 DOM `<a>` 元素的可靠映射，重复显示文本时不能随便取第一个同名节点。

### 4.2 编辑器层

优先考虑：

- `registerEditorExtension()`、CodeMirror 6 `ViewPlugin`、`Decoration`/`WidgetType`、`EditorView` 及准确的 viewport/selection 数据。
- `Editor` 接口用于执行用户真实的 Markdown 编辑，尽量避免对当前打开的笔记直接调用 `vault.modify()` 覆写全文。
- 编辑器内容是瞬时真相：编辑中的未保存文本不能依赖可能滞后的 `metadataCache` 位置直接覆盖。
- 正确处理多光标/多选区：MVP 可明确仅支持一个连续选区，其余提示不支持。
- 用显式锚点范围映射，而非只靠全文正则：应避免把代码块、行内代码、frontmatter、普通 URL、嵌入式语法里的字符串误判成可视化双链。可以结合 CM6 Markdown syntax tree 与必要的解析逻辑；对文档缓存优先采用官方 `MetadataCache` 提供的信息并验证原文语法。

### 4.3 阅读模式

优先使用 `registerMarkdownPostProcessor()`、`MarkdownRenderChild` 或官方等效生命周期接口。只在当前渲染中的真实 Wikilink 元素上建立虚拟连接信息；不要通过直接修改 Markdown 文件来插入锚点，也不要在 HTML 中执行用户文件内容。

### 4.4 解析与分辨同名文件

- 用 Obsidian 官方 `MetadataCache.getFirstLinkpathDest()` 或经过确认的等效 API 解析目标；合理处理源文件路径与最短链接、同名文件、子标题、块链接。
- 实际目标路径应在 UI 上可以看到，但**写入 Markdown 的仍是合法原生双链**。
- 创建双链时首选可精确指向所选文件的路径；若最短名称存在歧义，使用含文件夹的路径；非 Markdown 文件必须保留必要扩展名。
- 需检查具体版本的 `FileManager.generateMarkdownLink()` 行为：该 API 可能受用户“Use Wikilinks”设置影响；本项目要求创建的链接**最终必须是 `[[...|...]]`**，不能意外生成普通 Markdown 链接。可以用原生 API 协助确定路径，但输出格式需要校验。
- 遇到带有 `|`、`]]`、特殊 `#` 等不可安全表示的文本或目标，不要隐式改写原内容；给出明确错误提示并保持文件不变。
- 若库中出现文件 rename/delete/modify，刷新相关可见链接与卡片；原生自动链接重命名的行为由 Obsidian 本身负责，本插件不重新实现自己的全局重命名引擎。

### 4.5 布局与性能

- 卡片位置应由真实 DOM 尺寸/`getBoundingClientRect()` 与编辑器坐标映射实时计算，不以“第 N 行 × 固定行高”猜测坐标。
- 允许 SVG Bézier 曲线，不得遮挡文字或按钮；先满足对齐、滚动和无重叠，再优化动画。
- 对同侧卡片按目标 Y 排序，自上而下分配最小间距；超出容器可视高度时应裁剪、只渲染可见项或使用低干扰的折叠表现，不得形成超长悬浮层。
- 用 `requestAnimationFrame` 合并频繁的 scroll/resize/update；必要时 `ResizeObserver`、滚动事件和编辑器更新事件。销毁时正确注销监听器、observer、frame 和 DOM。
- 只为可见范围创建高成本图形；一篇含大量双链的长笔记仍应正常滚动。
- 不要对整个 Vault 周期性扫描或持续定时轮询。

### 4.6 拖拽状态机与安全修改

建议实现清晰状态：`idle → selection-ready → dragging → drop-accepted → choosing-file → validating → writing → idle`，以及任何阶段的 `cancel` 路径。

创建完成前必须校验：

- 仍处于原始源文件与原始编辑器上下文。
- 原选区范围可定位且文本未变化。
- 原选区未处于不允许的 Markdown 结构中。
- 用户选择的是能够可靠定位的已有文件。
- 生成的 Wikilink 没有语法破损且能指向预期目标，或按受限扩展格式规则提供清晰失败信息。

任何取消、失焦、失败、条件不成立都不写回 Markdown。成功写入要支持 Undo/Redo，且撤销后卡片同步消失。

## 5. 命令与设置

至少提供以下命令：

- `Toggle margin links` / `切换边缘关联显示`：只切换当前显示功能，不改 Markdown。
- `Link selected text to file` / `将选中文字链接到文件`：打开文件选择器并写入原生双链。
- `Refresh margin links` / `刷新边缘关联`：重新从当前双链与实际布局计算。

不预设全局快捷键。命令 ID 保持简洁，遵循 Obsidian 官方要求。

建议的设置（**仅限 UI 偏好**）：

| 设置 | 默认值 | 说明 |
|---|---|---|
| 启用边缘关联 | 开 | 主功能开关 |
| 连线显示方式 | 悬停高亮 | 可切换常显 / 悬停 |
| 卡片密度 | 自动 | 卡片 / 紧凑图标根据实际宽度切换 |
| 左右布局 | 自动平衡 | 不存储单条链接侧边位置 |
| 显示相对路径 | 悬停或必要时 | 用于同名文件消歧 |
| 视觉动效 | 尊重系统减少动画 | 支持 `prefers-reduced-motion` |

如果某项设置会显著增加复杂性且不是第一版必要功能，可先不提供，但不能为了支持它引入文件关联的持久化数据。

## 6. UI 质量与兼容性要求

1. 使用 Obsidian CSS 变量（如 `--interactive-accent`、`--background-primary`、`--text-normal` 等），避免硬编码色值，支持暗色/亮色主题。
2. CSS 类名统一用 `margin-link-` 前缀，不污染全局 `.markdown-preview-view`、`.cm-editor` 的其他内容；不覆盖用户主题中无关元素。
3. 不引入 React/Vue 等重量级框架，除非仓库已有而且有明确必要。
4. 文件类型优先使用 Obsidian 的 `setIcon` / 内置 Lucide 图标；找不到类型时用通用文件图标。
5. 不把 `innerHTML` 直接设为文件名、别名或未受信任 Markdown 文本，使用安全文本节点。
6. 不加载远程资源、无遥测、无广告、无外部请求；不开启 HTML 脚本执行，不做危险的 HTML 内嵌渲染。
7. 分屏、多标签、阅读模式、编辑模式切换时没有重复 UI、事件泄漏、僵尸曲线。
8. 在空间不足的窄视窗下安全降级；不强制撑宽应用、不能遮住笔记文字。
9. 尊重鼠标、键盘和触屏差异；MVP 以桌面鼠标键盘为主。提供可通过命令面板使用的无拖拽入口。
10. 使用官方插件生命周期管理所有注册与清理操作，卸载插件后不能留下图层或修改正文样式。

## 7. 明确不在第一版做的事情

不要将有限时间投入以下方向：

- 新的全局图谱引擎、独立 Canvas 编辑器或独立文件管理器。
- 自定义标签体系、关系数据库、知识图谱持久化、向量检索、云同步。
- HTML 文件浏览器/执行器、思维导图渲染器、PDF 深度标注器。
- 手动拖动卡片到任意像素坐标并持久保存位置（双链没有该信息）。
- 把一段文字同时链接多个不同文件的特殊语法；保持一个双链对应一次文件引用。
- 自动改写整篇笔记里的链接语法，或把普通 Markdown 链接批量强制改成 Wikilink。
- 在后台扫描整个 Vault 生成关系缓存。

## 8. 测试要求：必须实际运行自动化测试

选择与当前项目兼容的测试框架（例如 Vitest；若环境不支持则可采用 Node 自带测试工具）。至少覆盖以下可自动化的单元测试，并以纯函数拆分业务逻辑，便于测试：

### 8.1 Wikilink 识别与格式化

- `[[Note]]`、`[[Folder/Note.md|别名]]`、`[[Board.canvas|导图]]`、`[[product_release_stages.html|Early Access]]`。
- 同一行多个双链、同名别名重复出现、同一目标多次引用。
- `[[note#heading|别名]]`、`[[note#^block-id|内容]]` 保留子路径。
- `![[image.png]]` 不参与“普通双链卡片”；代码块、内联代码、YAML、普通 URL 和纯 Markdown 链接不误识别。
- 中文、Unicode、空格、相对路径、多个同名文件。
- 非法或无法可靠转义的别名不会造成损坏写入。

### 8.2 编辑与选区保护

- 选中普通文字时安全生成 `[[target|selected text]]`。
- 不选中文字、跨硬换行、选区包含双链或代码结构、已失效的 selection，均不会修改任何字符。
- 用户取消文件选择不会改写文档。
- 在文件选择器打开期间，源文件改变或选区内容被修改，则拒绝写入。
- 可以撤销/重做一次创建双链的操作（该部分如无法脱离 Obsidian 测试，须列为手工验收）。

### 8.3 边缘布局

- 多个相邻双链卡片不会互相重叠（给定矩形输入）。
- 左右可用空间不足时自动缩小或安全退化。
- 同样输入经过重算输出可重复且稳定。
- 不会生成 `NaN`、负尺寸、溢出容器的不可控坐标。

### 8.4 实际构建检查

至少执行并记录结果：

```bash
npm install
npm run build
npm test
npm run lint
```

如果项目没有配置其中某条命令，补齐脚本或清楚说明原因，不得谎称测试通过。必要时另外执行 `npx tsc --noEmit`。若依赖下载或环境限制导致不能执行，要明确说出未执行的原因和下一步命令。

## 9. 在 Obsidian 桌面端手工验收的场景

建立**单独的测试 Vault**（不要在用户正式笔记库中测试）。在 README 中提供以下可逐条验证的操作步骤：

1. 新建测试库，启用“限制行宽”，在笔记加入 `[[Note A|关键观点]]`，确认显示卡片与关联线。
2. 进入 Live Preview；选中 `Early Access`，拖动链接手柄至右侧空白，选择一个已经存在的文件；检查生成的原文是 `[[路径|Early Access]]`。
3. 从编辑器命令面板使用“将选中文字链接到文件”，完成相同效果。
4. 点击卡片能打开目标；悬停能关联高亮文字、节点、连线。
5. 切换 Source mode 和 Reading view，卡片仍对准真正的双链；阅读模式不会出现输入手柄。
6. 打开左右侧边栏、调整窗口和可读行宽、缩放字体、滚动长文、切换明暗主题，观察线与卡片不会明显错位或压住正文。
7. 两个 Markdown 视图并排打开不同文件，左右可视化不会串位。
8. 在一段双链之前插入很多新文字，位置正确重新计算。
9. 修改双链目标，卡片变化；撤销新增双链，卡片消失；再次重做，卡片恢复。
10. 删除或重命名目标文件，Obsidian 原生链接更新行为不受插件干扰，未解析状态不乱指向别的文件。
11. 尝试 `[[Board.canvas|导图]]`、`[[图像.png|截图]]` 和一个 `.html` 目标；说明 `.html` 在有/无文件类型处理插件时各自会怎样表现。
12. 取消拖拽、取消文件弹窗、选取跨段落文字、切换活动笔记再确认文件；验证原笔记不发生意外修改。
13. 关闭插件或卸载后，检查笔记的 Markdown 原文和原生双链没有丢失，也没有新增关系数据库/注释/元数据文件。
