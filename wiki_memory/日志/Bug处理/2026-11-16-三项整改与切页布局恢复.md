# 三项整改与切页布局恢复

## 目标与起点

按用户三项整改任务实现左 Ribbon 直达完整设置、移除卡片握柄改为整卡拖动、修复切页位置复位。2026-11-16 在 F:/myGithub/MarginLink 核实 main、origin/main、基线 51260ae9cfb14369a88c412743b6d3a43454f8bf；remote 为 DewMysimple/MarginLink，已有变化只有用户本轮任务提示词，未覆盖其他任务改动。

## 已核实原因与实现

- 旧版普通无延迟导航首轮未复现；真实隔离 Obsidian 1.10.6 的 Vault 读取加入 120ms 延迟后，A 路径与 B 的旧编辑器链接集合交叉，reconcile 删除 A 的有效内存布局，实际卡片和连线回到自动位置。证据 artifacts/layout-before-fix-delayed.json。
- 视图加载和阅读局部渲染不再触发布局清理；完整源文确认、文件绑定 metadata 清理、定向源路径 rename/delete、原有同步内存与串行落盘保护均已实现。CRLF/LF 统一身份并兼容旧 raw key，有单测及桌面恢复验证。
- 最终审查补上旧 raw 记录自动迁移：完整源确认/完整清理前定向迁移，保留原坐标与时间，首个完整快照已 LF 也可恢复。专项脚本先在迁移前构建红测，再在最终构建绿测，覆盖原生启用、模式/导航/重载后的实际矩形和连线。
- Ribbon/右侧 ItemView 复用完整表单；最近 Markdown 来源、并发打开单实例、关闭重开和卸载处理已实现。主插件生命周期单测覆盖异步面板和写入顺序。
- 卡片自身承载 pointer/click/键盘；阈值/合法落点沿用。桌面发现原生活动叶事件延迟取消首次拖动，已改为只取消非当前 Markdown 视图，真实三处起拖、三外观及取消/下一次打开均通过。
