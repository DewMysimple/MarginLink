# ADR-003 完整源文清理与整卡交互

## 授权与保留的边界

2026-11-16 用户明确要求完成三项整改。延续 ADR-002 的 schema 2、原生 Wikilink 唯一关系源、现有 data.json 中可清除的 UI 偏好、相对锚点坐标、500/100 条及 90 天限制。原文/上下文散列只作弱身份，歧义回退，不向 Markdown 写入身份或位置。

## 已采用的选择

- 用户指定左 Ribbon 直达右侧完整设置；Agent 采用公开 ItemView、registerView 和 leaf API，表单与原生设置页共用。只在用户打开时激活，已有标签即使移动也复用；最近操作的 Markdown 视图决定“当前笔记”，不因设置获得焦点丢失来源。
- 用户指定移除已有卡片握柄；Agent 将 pointer、click、键盘交互统一到卡片按钮。约 5 CSS px 阈值后拖动，合法 drop 同步更新内存并合并串行落盘；只抑制本次手势点击，取消恢复。正文选区建链手柄独立保留。
- Agent 移除 overlay/阅读后处理触发的破坏性 reconcile。清理只接受 metadataCache.changed 携带的完整源文件内容，并跳过与同源未保存编辑器不一致的旧快照。加载和部分渲染不能证明双链被删除。
- 新源与完整内容确认一致后才渲染和提交，过期异步读取丢弃；有限退避重试避免加载停滞。换行差异只用于身份兼容与比较，不改文件字节。完整源确认/清理前安全迁移可唯一匹配的旧 CRLF key，保留坐标与时间；LF 首次快照只考虑精确 CRLF 等价全文，歧义不迁移。
- 替代 ADR-002 全局 rename/delete 失效：源路径及子目录定向迁移/删除；目标变化仍由真实原生双链及唯一身份决定是否匹配。无关附件不能清空其他笔记的布局。
- 窗口变化、侧栏动画、锚点离屏只调整显示，不覆盖保存值。激活新 Markdown 标签时只取消其他视图的手势，避免延迟活动事件取消刚开始的整卡拖动；文件切换仍全部取消。

## 原因与代价

隔离 Obsidian 1.10.6 加入 120ms Vault 读取延迟后，真实导航出现 A 路径 + B 编辑器链接集合，旧 reconcile 清空 A 记录，卡片从手动右侧回到自动左侧。普通无延迟导航首轮未复现。完整证据见 VALIDATION 与 artifacts/layout-before-fix-delayed.json。

安全优先：加载期间卡片可暂时隐藏，真实上下文/重复引用数量变化仍会使对应位置回退。未验证平台与第三方组合继续按验证报告列明；不能把隔离 Windows 结果外推所有环境。
