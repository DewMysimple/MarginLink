# 已知问题

## 未解决问题与影响

1. **宿主/CDP 告警**：本机 1.15.0 更新包与 1.10.6 安装程序组合，在自动切主题并关闭独立设置窗口时出现 6 条无堆栈 `illegal access`。26 项功能场景通过；卸载所有社区插件后仍复现相同告警，具体宿主原因未确认，不能归因于插件或宣称已修复。见验证报告及原始 JSON。
2. **特殊类型打开限制**：公开 API 不能枚举未打开的第三方处理器，HTML 等即使已解析/已安装处理器，也可能因缺少已打开的兼容 FileView 而提示不支持。这是明确降级。
3. **首版选择与布局边界**：拒绝表格内创建、复杂格式/多选区/硬换行及不可安全表达的别名/路径；转义 Wikilink 保守跳过。密集或窄视图会省略卡片，卡片位置不持久化。这些是已记录的边界，不是链接丢失。
4. **阅读 DOM 与兼容缺口**：第三方改写同一目标链接数量可能使该目标组无法消歧而不显示。尚未覆盖用户主题、popout 编辑窗口、其他系统/RTL、全部媒体编解码格式及查看器组合。

## 复现与临时处理

- 告警：隔离库启用 1.15.0 更新包，运行 `npm run test:desktop` 查看主题关闭阶段及 `artifacts/desktop-diagnostics.json`。需要对照时在 PowerShell 先设 `$env:MARGINLINK_THEME_CONTROL='1'`，执行同一命令，结束后移除该环境变量；对照模式会临时卸载社区插件并恢复列表，不能替代启用插件的验收。后续在正常鼠标操作及更新安装程序下复核，不过滤新增异常。
- 特殊类型：先经相应处理器打开同类文件，保留兼容标签，再激活卡片；没有处理器时保留原生双链和提示，不做替身转换。
- 选择/布局：在普通行内文本用手柄或命令；空间不足可增大视图或调整可读行宽。卡片隐藏不修改 Markdown；复杂结构不尝试强行写入。
- 阅读兼容：先在默认主题、关闭第三方 DOM 改写的独立库比较，再收集最小复现，检查 `src/reading/source-mapping.ts`，不能直接匹配第一个同名别名。
